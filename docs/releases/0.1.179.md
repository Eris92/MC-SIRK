# 0.1.179 - Move Request requester/approver separation and OK dialog

- Correct 0.1.178's wrong security model: a regular user may submit a Move Request without `MESHRIGHT_EDITMESH`, provided they can access the selected source device and the destination is a compatible visible mesh in the same domain.
- The existing Approval Center level/group policy continues to determine who may approve. On final approval, execute using the final approving user's MeshCentral identity; enforce native edit rights for both source and destination, plus same-domain/type validation. Do not impersonate an administrator or bypass MeshCentral permissions.
- For target groups requiring privileged moves, ensure members of the configured approving group also hold source+target Edit Mesh permissions in MeshCentral. Approval group membership alone does not grant native mesh rights.
- After a successful POST, the native dialog keeps its success message, changes the primary action to OK, enables it and hides Cancel. OK closes through the existing Modern/Classic MeshCentral dialog manager, with no separate modal or timer.
- The error path keeps the form for correction and resubmission; rapid repeats cannot duplicate requests.
- Developer revision only, no tag or GitHub Release; real MeshCentral smoke remains required for #265.
