# 0.1.148 (2026-11-04)

Status: development build, not released.

## Nessus "Repair" column
- The CSV may carry an 18th column named `Repair` (last). A 17-column file is accepted unchanged; any other 18th header is rejected.
- Values: empty, `0`, `no`, `nie`, `false`, `n` = open. A date (`YYYY-MM-DD`, with optional time) = repaired at that time; a date without a time counts as the whole day. Any other text (`yes`, `tak`, `true`) = repaired.
- A dated repair older than the scan's generation date means the scan still found it, so the finding is shown again.

## Repairs recorded by the portal
- When a pinned remediation command (vulnerability rule) run on a host from Commands, Quick or approval returns a result that is not failed/error (`captureAgentData`), the matching findings are recorded once in `sirk-platform-data/nessus/repairs.json` (host, Plugin ID, time, user, command) and an audit event `repair` is dispatched (counts and Plugin IDs only).
- A failed run or an offline agent records nothing, so the finding stays visible. Running the pinned rollback command (successfully) removes the mark. A newer scan of the host supersedes older marks.

## Host matching by name only
- Snapshot hosts are keyed by host name without domain (`Host`, or `Host Original` when `Host` is an IP): `PC01`, `pc01.corp.local` and `pc01.other.local` are one host, so a machine listed under several names in one scan is no longer "ambiguous".
- A device matches by its agent computer name (`rname`) and device name, domain stripped. IP addresses are never used (DHCP); `node.host` is ignored.
- "Ambiguous" remains only when the computer name and the device name point to two different hosts.
- Snapshot schema 2; an older `snapshot.json` is rebuilt from the CSV on the next read.

## Views
- Repaired findings are hidden in Quick and Commands and excluded from counts and the Desktop alert. Commands shows them with the "Excluded / repaired" toggle, with "repaired" and Undo.
- My Scripts all-host table: "Repaired" fix filter; "active" hides repaired; export gains a `Repair` column (CSV value or portal repair time).
