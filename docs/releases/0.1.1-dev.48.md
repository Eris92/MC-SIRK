# MC-SIRK 0.1.1-dev.48

Status: development pre-1.0 candidate do realnego MeshCentral smoke; brak tagu/GitHub Release.

## Zakres

- Issue #128: zachowany jest ręcznie potwierdzony body `Status=Up -> Namespace(49) -> Properties/Właściwości -> FolderItemVerb.DoIt()`, natomiast trusted `Network Settings` nie uruchamia już drugiego `powershell.exe -NonInteractive` wewnątrz elevated user-session tasku. Polecenie wykonuje się bezpośrednio w tym samym `RunLevel Highest`, interactive `-STA` runnerze; zwykłe `runAsUser` PowerShell nadal zachowują izolowany child-process contract.
- Issues #280/#281: shared native parameter/confirmation lifecycle dla My Scripts/My Commands oraz Script credentials/System credentials oparte o istniejące encrypted owners; Jira/Active Directory/AAD-Entra w Admin pozostają write-only i collapsed-by-default.
- Issue #284: standalone Script credentials jest widoczne tylko dla zapisanych lokalnych `SaveSecret` / `SaveSecretRequired`; System credentials pozostają dostępne w Definition Editor niezależnie od local secrets.
- Issue #285: Definition Editor neutralizuje hostowe hover/focus transform/scale/zoom bez przejmowania native kolorystyki i bez JS hover handlers.
- Issue #286: znane profile System credentials można przypisać przed globalnym configured state; runtime nadal failuje zamknięcie dla assigned-but-unconfigured i nie ujawnia sekretów. Definition Editor nie połyka błędu zapisu assignmentu.
- Issue #287: Favorites/Edit/Multi współdzielą gold active-icon contract, przy zachowanym `aria-pressed`; Edit/Multi nie używają persistent selected whole-button surface.
- Issue #288: Quick `ConfirmExecution` używa istniejącego native MeshCentral confirmation dialogu zamiast `window.confirm()`, zachowując parameter values i exactly-one submit.
- Nie dodano drugiego secret store, modal frameworka, polling loop, observera ani per-row credentials requestów.

## Weryfikacja

- PR #289 exact-head Linux `npm test` oraz Windows interactive-shell smoke są wymaganym merge gate.
