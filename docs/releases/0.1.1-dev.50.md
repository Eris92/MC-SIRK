# SIRK Management Platform 0.1.1-dev.50

Date: 2026-08-11

## Jira wizard corrective follow-up

Real Jira + MeshCentral smoke on `0.1.1-dev.49` exposed a Modern native-dialog lifecycle bug in the four-step Jira Asset Protocol wizard: after accepting the first `Jira users` scope dialog, the modal closed and the wizard did not advance.

Root cause: `public/modules/automation/jira-protocol-wizard.js` added a second `hidden.bs.modal` wait after the shared parameter dialog promise had already resolved. MeshCentral's native `showModal()` lifecycle is authoritative for closing the dialog and does not guarantee that this extra listener will receive another hidden event. The wizard could therefore remain pending forever after step 1.

Fix:

- chain the next wizard step directly from the existing shared `openParameterDialog()` promise;
- remove the duplicate Modern modal-hidden readiness owner;
- keep the same four native shared steps and provider context;
- add a negative regression where the modal still reports `show` and any attempt to attach the obsolete extra hidden listener fails the test;
- no polling, timer, MutationObserver, custom modal framework or browser prompt.

Issue #290 remains open until real Jira + MeshCentral re-smoke confirms all four steps and the final protocol execution/PDF path.

No tag or GitHub Release.
