# SIRK Management Platform 0.1.1-dev.53

Date: 2026-08-11

## Shared dynamic-option provider bridge correction

Real `0.1.1-dev.52` Jira + MeshCentral smoke confirmed that the first Modern wizard transition now completes correctly, but the User step contained only the placeholder and could not continue.

The shared parameter-dialog owner registered dynamic User/Asset providers globally, while My Scripts correctly worked through the instance returned by `SharedScriptTools.create()`. That instance bridge exposed the shared open methods but omitted `setParameterOptionProvider`, so the Automation provider-registration guard never ran and the User/Asset controls silently fell back to empty static options.

`0.1.1-dev.53` extends the existing instance bridge with the shared provider setter and adds a focused regression proving that an instance registration reaches the one shared provider owner. No parallel provider, Jira-local loader, timer, polling, MutationObserver or custom modal was added.

The resumed real smoke also identified a script-owned data-scope error: `objectType = Computer` selected the LanSweeper `Computer` type, whose four returned records have no Jira user assignment. The actual managed-user inventory is the CMDB `Komputer` type with `Osoba_odpowiedzialna` references and `Nazwa_sieciowa` as its network-name attribute. The canonical protocol metadata now targets that confirmed CMDB type while preserving the required `JiraUser` binding.

The first real execution then exposed Windows PowerShell 5.1 command-expression ambiguity inside nested result hashtables. Protocol environment-value helper calls are now explicitly parenthesized, allowing the structured result to reach the protected PDF renderer.

Repeated smoke execution also confirmed that Modern `showModal()` can reapply the host's previous disabled state to the shared OK button. The parameter-dialog owner now performs its final submit-state synchronization immediately after the host show call, keeping each new wizard step actionable without a timer or observer.

The canonical Polish PowerShell protocol remains UTF-8 with BOM, which is required for Windows PowerShell 5.1 to parse its native text and produce a correctly encoded result/PDF.

Inspection of the installed MeshCentral `showModal()` contract confirmed that its own `hidden.bs.modal` handler disposes and clears the shared modal instance. MC-SIRK now registers its hidden resolver only after `showModal()` has installed that native owner, so host cleanup runs first and the next wizard step receives a fresh enabled modal.

Targeted shared parameter-dialog and Jira wizard tests plus the complete repository suite are required before merge. Issue #296 tracks the real Jira/MeshCentral smoke through User, Asset, Protocol and protected PDF.
