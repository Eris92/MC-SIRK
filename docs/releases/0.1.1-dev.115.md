## Jira Asset Protocol #355 live equipment search follow-up

Real MeshCentral feedback on `0.1.1-dev.114` showed that Search in the `Sprzęt z magazynu` / `Sprzęt użytkownika` steps refreshed only after committing the custom input value, typically by pressing Enter or leaving the field.

Root cause:

- the shared parameter dialog treated those Search fields as custom `user` dependencies;
- ordinary user dependencies intentionally refresh on the `change` event;
- the Jira equipment Search therefore did not invoke its already-local prefetched-array filter for every typed character.

Changes:

- keep `public/shared/ui/parameter-dialog.js` as the single event/lifecycle owner;
- add an opt-in `liveInput` flag for custom user dependencies and reuse the existing `onUserChanged` handler on the `input` event;
- keep ordinary user dependencies on `change`, avoiding provider churn outside explicitly live inputs;
- mark both Jira equipment Search controls as `liveInput: true`;
- keep the existing local search provider over the one prefetched inventory, so typing performs no Jira request per character;
- add no wizard-local event handler, observer, timer, polling loop or second renderer.

Verification:

- targeted Jira wizard regression checks that both equipment Search controls opt into live input;
- shared parameter-dialog regression checks symmetric input listener attach/cleanup and preserved change-only behavior for ordinary users;
- full `npm test` and Windows interactive-shell smoke must be green on the exact dev.115 PR head before merge.
