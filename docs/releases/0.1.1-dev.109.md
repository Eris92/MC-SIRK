## Scope

Restore the last real-smoke-proven Jira protocol/cache source scope after dev.108 expanded the canonical workflow to the whole Assets workspace and a forced `Cache - sprzęt` refresh returned 26,582 source objects.

## Root cause

Dev.108 changed both canonical workflow headers from `objectType in objectTypeAndChildren("Sprzęt użytkownika")` to workspace-wide `Key is not EMPTY`. The shared Jira service then correctly fetched and truthfully reported the complete workspace snapshot, so the observed 26,582 count was a direct consequence of the widened source contract rather than a cache-count defect.

- Restore `Cache Assets` to the same scope so the explicit cache and protocol reuse the same persisted snapshot.
- Keep dev.108 authoritative `/object/aql/totalcount` pagination and truthful `sourceCount` reporting unchanged.
- Keep current user-cache v2, Assets cache v4, bounded concurrency/safety limits, user/reference matching, PDF/UI/scheduler and credential ownership unchanged.
- Update regressions to pin the proven scoped source and reject accidental `Key is not EMPTY` reintroduction.
