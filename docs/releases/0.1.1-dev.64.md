# SIRK Management Platform 0.1.1-dev.64

## Windows service-safe Jira protocol PDF rendering

Real MeshCentral/Jira smoke reached the final styled PDF stage but Microsoft Edge exited before creating `protocol.pdf` when launched from the MeshCentral Windows service context.

`server/core/html-pdf-renderer.js` now keeps the existing local Chrome/Edge renderer but starts every render with a unique writable browser profile inside the already-bounded temporary render directory. The same directory is used as browser `cwd`; first-run/default-browser startup paths are suppressed; the complete temporary tree is removed after success or failure.

Browser-process failures now include bounded stdout/stderr diagnostics instead of exposing only the failed command line.

Regression coverage verifies the isolated `--user-data-dir`, writable working directory, PDF output path, cleanup, and bounded browser diagnostic propagation. No external PDF dependency, persistent browser profile, polling loop, tag, or GitHub Release is introduced.
