# 0.1.165 (2026-11-05)

Status: development build, not released. Request: the certificate template (and RDP signing thumbprint) can differ per script, so it should not be only one global value.

- `server/core/integration-service.js`: `caScriptOverrides(headers)` / `caForScript(globalCa, headers)`. Header lines `SirkCaTemplate:` and `SirkRdpSigningThumbprint:` override the global template/thumbprint for one script; empty header = global default. Same validation as the global settings; invalid header fails closed.
- `server/core/script-admin-service.js`: `caVariables` (My Commands, agent side) and new `caSettings` (My Scripts, server side) use the merged values. `server/core/server-script-executor.js` feeds `MYSCRIPTS_CA_*` from `admin.caSettings`.
- Settings → Integrations → CA: template and thumbprint labelled as optional defaults, with the header syntax explained.
- Seed: `Sign CSR.ps1` gets an empty `# SirkCaTemplate:` line; `Generate signed RDP file.ps1` an empty `# SirkRdpSigningThumbprint:` line; error messages name both places.
- Permissions unchanged: Sign CSR runs as the MeshCentral service account (needs Read + Enroll on the template); the RDP command runs as SYSTEM on the device and needs the signing certificate with private key in LocalMachine\My.
- Verification: `test/ca-integration.test.js`, `test/csr-signing.test.js`, full `npm test`. No tag or release.
