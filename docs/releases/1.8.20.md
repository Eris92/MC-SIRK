# MC-SIRK 1.8.20

- wykonano końcowy pre-handoff cleanup kodu, testów i odpowiedzialności runtime;
- usunięto historyczne warstwy compatibility: `download-results.js`, `script-edit-actions.js`, `mesh-plugin-core.js` i `quick-output-state.js`;
- usunięto stary snapshot regresyjny `ui-regression-1.8.19.test.js` i przepięto testy na aktualnych właścicieli funkcji;
- usunięto nieużywane helpery `directivesText()` i `parseDirectives()` z `script-tools.js`;
- scentralizowano natywny wygląd w `MeshThemeAdapter`; plugin nie utrzymuje własnych stanów hover/selected dla standardowych list i przycisków MeshCentral;
- przeniesiono globalną geometrię workspace do statycznego `shared-ui.css`, pozostawiając `layout.js` jako właściciela struktury i stanu Collapse;
- usunięto duplikaty CSS ownership: Collapse track ma jednego właściciela, tree indentation należy wyłącznie do `shared-ui.css`, a nadpisywane `table-layout:auto` i zbędne `gap:0` zostały usunięte;
- zaktualizowano architecture/test contracts tak, aby blokowały ponowne dublowanie tree indentation w `toolbar.css`;
- przywrócono wspólny Collapse dla Approval Center, Commands i My Scripts wraz z migracją istniejącego stanu;
- naprawiono atomic render modułów i przełączanie SIRK -> SIRK bez pośredniego odtwarzania Devices;
- naprawiono wzajemne wykluczanie Edit/Multi i bezpośrednią synchronizację natywnych klas toolbaru;
- Quick ma jednego właściciela stanu Output/attention, bez dodatkowego controllera, obserwatora DOM i legacy `data-*` state;
- usunięto compatibility CSS Quick, ustabilizowano launcher 38 px i zachowano canonical układ kolumn;
- scentralizowano request timeout/cancellation dla GET w `SirkPlatformCore.api()`;
- scentralizowano obsługę wygenerowanych CSV w `results.js` i chronionym endpointcie `admin.js`;
- usunięto stare brandingowe wpisy `My Company` z audytu wykonywania poleceń;
- zsynchronizowano `package.json` i `config.json` do wersji `1.8.20`;
- CI zaktualizowano do Node.js 24, `actions/checkout@v7` i `actions/setup-node@v7`;
- pełny `npm test`, security regression, repository layout i architecture validation przechodzą poprawnie.
