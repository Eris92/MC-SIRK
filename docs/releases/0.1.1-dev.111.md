## Jira Asset Protocol #355 real-smoke correction

Real `0.1.1-dev.110` MeshCentral smoke exposed a wizard failure after the first equipment modal: `Jira protocol equipment controls are unavailable.`

Root cause: the Jira wizard attempted to post-process `.mc-parameter-dialog-content .mc-parameter-checklist` after opening the shared native dialog. `parameter-dialog.js` passes only the wrapper `innerHTML` to MeshCentral, so the outer `.mc-parameter-dialog-content` node is not part of the live host modal and the post-processing lookup was invalid.

This revision removes that live-DOM operation injection and changes the protocol flow to two explicit optional equipment steps backed by the same prefetched Jira protocol inventory:

1. `Sprzęt z magazynu` — searchable multi-selection of equipment to hand over to the selected user; selected stable Jira asset IDs map to `receive`.
2. `Sprzęt użytkownika` — searchable multi-selection of the selected user's current equipment to return; selected stable Jira asset IDs map to `return`.

Both Search controls filter the already-prefetched option arrays locally. No request per row, per option or per search is added. The wizard still emits the existing bounded stable-ID action-map contract consumed by the canonical Jira protocol service.

Preserved without changes:

- requester/Site Admin `awaiting_confirmation` lifecycle;
- protected PDF generation before any Jira Assets write;
- authoritative current/final inventory calculation;
- live ownership/schema verification before final mutation;
- replay/stale-state guards and partial-failure behavior;
- explicit Open/Download PDF lifecycle;
- dev.109 `objectType in objectTypeAndChildren("Sprzęt użytkownika")` source scope and Jira cache ownership;
- no new timer, observer, polling loop, per-row handler or parallel Jira workflow.

No tag or GitHub Release is created for this development revision.
