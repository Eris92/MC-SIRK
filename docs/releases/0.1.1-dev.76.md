## Jira all assigned equipment follow-up

Real `0.1.1-dev.75` smoke confirms the restored dev.64 path is valid again: Jira equipment selection works and protocol PDF generation completes. The remaining acceptance failure is scope: the source hierarchy returns PC-class equipment only.

This build keeps the working `Sprzęt użytkownika` hierarchy as a compatibility anchor and extends the canonical Jira Asset Protocol/cache AQL only to objects participating in the Assets reference graph:

- `object HAVING outboundReferences()` includes equipment and other objects that reference another Assets object;
- `object HAVING inboundReferences()` includes the referenced identity/person objects needed by the existing server-side Jira-user alias bridge;
- the existing server-side user binding still decides which objects belong to the selected Jira account and excludes the identity object itself;
- the failed workspace-wide `Key is not EMPTY` source is not restored;
- existing bounded pagination, compact cache, authoritative protocol recheck and PDF lifecycle are unchanged.

The intended result is that the already-working PC path remains available while referenced phones, monitors and other Jira object types assigned to the same user can be returned by the same shared service.
