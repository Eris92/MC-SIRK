Status: development pre-1.0  
Date: 2026-08-18

## AD reset selector latency and Windows PowerShell SMS UTF-8 correction

Real MeshCentral/SMSAPI smoke rejected `0.1.1-dev.122`: the reset user list still appeared only after a long delay and received create/reset SMS text still lost Polish characters.

Root cause / decisions:

- the Jira-backed reset path still started a full `Get-ADUser -Filter *` enumeration of up to 10,000 directory users whenever the selector opened; this dominated the dialog latency even when the Jira users cache was already fresh;
- the Windows PowerShell 5.1 SMS helper still handed Unicode form values to `Invoke-RestMethod`; declaring `charset=UTF-8` and SMSAPI `encoding=utf-8` did not guarantee that PowerShell's form encoder preserved those characters before transport;
- keep the existing Jira cache, AD directory owner and shared local Search instead of adding another cache, browser request loop or background poller.

Changes:

- `server/core/ad-directory-service.js` now extracts normalized unique Jira `emailAddress` values and asks AD only for those `UserPrincipalName` identities using escaped LDAP OR filters in bounded chunks of 500;
- one PowerShell process owns the AD match. Large Jira identity sets are streamed through stdin instead of being placed in the Windows environment/command line, and stdin write failures are handled through the same bounded error path;
- the normal reset workflow no longer enumerates the full Active Directory. The historical full-directory path remains only as a fallback when no Jira cache owner is injected;
- if the Jira cache contains no usable e-mail identities, the AD query is skipped entirely;
- the existing `emailAddress -> UserPrincipalName` case-insensitive match and AD-safe `sAMAccountName` option value are preserved;
- `seed/MyScripts/_shared/Sirk-AdSms.ps1` percent-encodes number, message and sender with `.NET Uri.EscapeDataString()` before `Invoke-RestMethod`, making the outbound form ASCII-only while retaining `encoding=utf-8` and `application/x-www-form-urlencoded; charset=UTF-8`;
- no per-user process, per-keystroke AD/Jira request, timer, observer, polling loop or second cache owner is added.

Verification:

- `test/sms-ad-real-smoke-regression.test.js` verifies one-process bounded LDAP matching, large-input stdin transport, no full-directory scan on the Jira-backed hot path, empty-identity short-circuit and ASCII-safe SMS form construction;
- the maintained Windows CI runner executes `test/windows-sms-utf8-smoke.ps1` under Windows PowerShell 5.1. The fixture is built from Unicode code points and must produce the exact UTF-8 percent-encoded form for `Zażółć gęślą jaźń`;
- existing `test/sms-ad-workflows.test.js`, localization, integration, security, Jira cache/protocol and requester confirmation/cancellation regressions remain part of the full `npm test` gate;
- exact `0.1.1-dev.123` Linux full suite and Windows smoke are required before merge.

No tag or GitHub Release is created. Issue #382 remains OPEN until real MeshCentral/SMSAPI smoke confirms prompt reset-list availability and correct Polish characters in the received SMS.
