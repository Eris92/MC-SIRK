# SIRK Management Platform 0.1.1-dev.79

**Status:** development pre-1.0

## Zakres

- Zachowuje proven `0.1.1-dev.75` Jira Asset Protocol / Jira Cache Assets AQL: `objectType in objectTypeAndChildren("Sprzęt użytkownika")`.
- Rozszerza wyłącznie istniejący server-side assignment-semantic classifier w `server/core/jira-asset-service.js` o angielski stem `responsible` i polski stem `odpowiedzialn`.
- Dzięki temu plain Jira Assets values z pola takiego jak `Osoba_odpowiedzialna` są traktowane jako przypisanie do wybranego Jira usera również dla heterogenicznych child object types, np. Monitor, Drukarka lub Tablet.
- Nie zmienia cache schema v4, AQL, pagination/concurrency bounds, user identity exclusion ani PDF renderer/lifecycle.

## Root cause

Jira schema używa wspólnego pola `Osoba_odpowiedzialna` dla sprzętu pod `Sprzęt użytkownika`. Gdy Jira zwracało relację jako structured `user` / `referencedObject`, istniejący matcher poprawnie wiązał asset. Gdy ten sam atrybut był zwracany jako plain `value` / `displayValue`, matcher dopuszczał go tylko dla nazw rozpoznanych jako assignment-semantic. `Osoba_odpowiedzialna` nie pasowało do dotychczasowej listy, więc taki asset był odrzucany mimo poprawnego AQL.

## Regression coverage

`test/jira-asset-responsible-person-attribute.test.js` modeluje `Komputer` i `Monitor` przypisane do jednego usera przez plain `Osoba_odpowiedzialna` oraz `Tablet` przypisany do innego usera. Oczekiwany wynik zawiera dokładnie `Komputer` i `Monitor` wybranego usera.

## Real environment acceptance

Po instalacji należy wykonać real MeshCentral/Jira smoke dla usera mającego co najmniej dwa różne typy sprzętu oraz sprawdzić końcowy Protocol -> PDF. PDF code w tej rewizji pozostaje bez zmian względem proven dev.75 path.
