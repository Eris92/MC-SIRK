# SIRK Management Platform 0.1.1-dev.79

Date: 2026-08-13
Status: development pre-1.0, real MeshCentral/Jira acceptance pending

## Scope

Real `0.1.1-dev.75` smoke confirmed with the tenant's actual Jira Assets schema (`Sprzęt użytkownika` with `Komputer`, `Monitor`, `Drukarka`, `Tablet`, ... as children, all sharing the same `Osoba_odpowiedzialna` assignment attribute) that `Sprzęt do protokołu` still returned only `Komputer` objects.

## Root cause

`server/core/jira-asset-service.js` binds an equipment object to the selected Jira user through explicit structured references (`user`, `referencedObject`) unconditionally, but falls back to matching a plain attribute value (`displayValue`/`value`/`searchValue`) only when the attribute's own name matches a hardcoded assignment-semantic word list (`owner`, `user`, `assigned`, `employee`, `pracownik`, `uzytk`/`użytk`, `przypis`, `wlasciciel`/`właściciel`). The tenant's real assignment attribute is named `Osoba_odpowiedzialna` ("responsible person"), which does not contain any of those stems. Where the Jira Assets `User`-type attribute response serializes as a plain value rather than a `.user`/`.referencedObject` structure, the plain-value gate rejected the match for every object type — including the same `Osoba_odpowiedzialna` field that happened to work for `Komputer` only when its response shape included a structured reference.

## Changes

- Extend the `assignmentAttribute()` word list in `server/core/jira-asset-service.js` with `responsible` / `odpowiedzialn`, so a plain-value `Osoba_odpowiedzialna` attribute is recognized as an assignment field on every object type, not only `Komputer`.
- Add a focused regression (`test/jira-asset-responsible-person-attribute.test.js`) that reproduces a `Komputer` and a `Monitor` object sharing a plain-value `Osoba_odpowiedzialna` attribute and asserts both are returned for the selected user.
- Keep the existing structured-reference matching, identity-object bridging (dev.73/dev.74), compact cache v4, bounded concurrency and the dev.75 canonical `objectType in objectTypeAndChildren("Sprzęt użytkownika")` scope unchanged.
