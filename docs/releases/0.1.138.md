# SIRK Management Platform 0.1.138

## Jira Assets human attribution after protocol confirmation

Issue #420: Jira Assets History retains the API credential identity because its built-in event is authored by the service account. After the requester or Site Admin confirms the prepared Jira Asset Protocol, MC-SIRK adds a separate per-object comment documenting:

- the receive/return business change and selected Jira user;
- the authenticated MeshCentral confirmer login and full name, resolved server-side;
- the original requester login and full name when a different Site Admin confirms;
- the immutable MC-SIRK protocol request ID.

No comments are created during PDF preparation, on reconciliation/no-change protocols, for stale assets, or before a verified ownership PUT/GET. Authentication and confirmation permission checks remain with the existing approval-service. Comment failures after a verified ownership update are reported as partial update/audit failures; they must not be shown as a fully audited success.

### External integration constraint

**Important:** As of 2026-10-22 Atlassian Cloud Assets REST API does **not** document a public object-comment create operation. MC-SIRK uses the Basic Auth `/v1/comment/create` endpoint for the additional comment. This is **unsupported/private** and may change or be unavailable in a particular tenant. Object History remains reliable for the technical API actor; comment-based human attribution requires a real Jira tenant smoke and must not be considered independently compliant audit evidence without it.

References:
- https://developer.atlassian.com/cloud/assets/rest/api-group-object/
- https://jira.atlassian.com/browse/JSDCLOUD-11505
- https://jira.atlassian.com/browse/JSDCLOUD-19802

No Jira token or Authorization header is included in comment contents, output or logs. No new configuration keys, timer, polling loops or dependencies were introduced. No tag/GitHub Release.
