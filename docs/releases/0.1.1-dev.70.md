# SIRK Management Platform 0.1.1-dev.70

## Jira AQL attribute metadata and Assets cache correction

Real `0.1.1-dev.68` smoke confirmed that a forced workspace-wide Assets cache eventually completed with `5000 items`, but the protocol returned no equipment for known assigned users. The Jira `/object/aql` response stores canonical attribute definitions in top-level `objectTypeAttributes`, while each object attribute contains only `objectTypeAttributeId`.

`0.1.1-dev.70` applies those response definitions directly to every returned page before caching and user-assignment filtering. This removes unnecessary sequential attribute-definition requests for object types already described by Jira and preserves the names required to recognize assignment fields such as Owner/User.

The Assets cache schema advances to v2 so snapshots written without attribute names are rejected and rebuilt once. The workspace-wide AQL, pagination bounds, secure server-side Jira credentials and heterogeneous assigned-object support remain unchanged.
