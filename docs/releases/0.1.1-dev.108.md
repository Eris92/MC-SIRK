# SIRK Management Platform 0.1.1-dev.108

Date: 2026-08-14
Status: development pre-1.0, real MeshCentral/Jira acceptance pending

## Scope

Correct Issue #305 against its canonical acceptance criteria after real dev.107 smoke showed a long forced Assets refresh and a misleading `5000 items` completion result.

## Root cause

Two separate problems were present:

1. `server/core/jira-asset-service.js` kept following Jira `hasMoreResults` after the page response hit the Atlassian-capped `totalFilterCount=1000`. That was intentionally added in dev.107 to avoid truncation, but without consulting Jira's dedicated authoritative total-count API it could keep scanning far beyond the real result set and make Force refresh unnecessarily long.
2. `server/modules/automation/index.js` reported `result.items.length` for the cache workflow. That array is intentionally capped by the interactive option limit (`5000`), so `5000 items` meant "the UI ceiling was reached", not "the cache contains exactly 5000 Jira objects".

Additionally, dev.107 retained the restrictive `objectTypeAndChildren("Sprzęt użytkownika")` AQL even though Issue #305 explicitly requires workspace-wide Assets input followed by server-side selected-user binding.

## Changes

- When the current Jira Assets response exposes capped `totalFilterCount` and `hasMoreResults`, use Atlassian's `POST /object/aql/totalcount` once to obtain the authoritative full count.
- Schedule exactly the remaining required 500-object pages with the existing concurrency bound of 3 and stop at the authoritative end.
- Keep the existing 50,000-object / 100-page and 180-second safety bounds; fall back to bounded sequential `hasMoreResults` pagination if the total-count endpoint fails.
- Expose the fetched source snapshot count separately from the interactive option list ceiling.
- Cache workflow completion now reports the source snapshot count; a 50k safety-bound result is reported as `at least 50000 items (bounded)` rather than as a false exact value.
- Restore Issue #305 workspace-wide AQL `Key is not EMPTY` in both `Jira Asset Protocol` and `Cache Assets`; selected-user filtering remains server-side.
- Preserve Jira user cache v2, Assets cache v4, explicit/reference/`Osoba_odpowiedzialna` matching, current PDF/UI/scheduler behavior and existing credential ownership.
