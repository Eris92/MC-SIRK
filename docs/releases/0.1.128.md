# SIRK Management Platform 0.1.128

**Status:** development pre-1.0  
**Date:** 2026-08-19

## Evidence

Real Issue #382 feedback after merged `0.1.127` is still unchanged for the user-visible problem, and the user explicitly narrowed this iteration to the received AD account SMS text: Polish diacritics are arriving as mojibake.

Earlier transport corrections (`encoding=utf-8`, UTF-8 form charset and ASCII-safe percent encoding) are retained, but they have repeatedly failed real received-message acceptance. This revision therefore does not add another encoding layer or touch the AD selector.

## Changes

- Change only the AD create/reset SMS wording to Polish text without diacritics:
  - `Konto w domenie <domena>, zostalo utworzone. Tymczasowe haslo:`
  - `Haslo w domenie <domena>, zostalo zmienione. Tymczasowe haslo:`
- Keep the requested blank line and temporary password.
- Keep login/UPN out of the SMS.
- Keep Polish UI labels unchanged.
- Keep the existing SMSAPI transport and DirectoryServices selector implementation unchanged.
- Add a regression proving both AD-account `$smsText` lines are ASCII-only, so those messages contain no encoding-sensitive Polish code points that can become mojibake after provider transport.

## Verification target

- `node test/sms-ad-workflows.test.js`
- full `npm test`
- existing Windows SMS/AD/installer smokes in CI

## State

Issue #382 stays OPEN until one actually received create/reset SMS confirms the new ASCII-safe Polish wording. The reset-selector behavior is intentionally not changed in this user-requested iteration. No tag or GitHub Release is created for this development revision.
