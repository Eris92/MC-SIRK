## Network root cause / change

The actual shared execution chain still intercepted every `runAsUser: 2` command in `logged-on-user-command-policy` and rewrote it to a SYSTEM command that launches a hidden Scheduled Task/WScript/PowerShell runner in the logged-on user's session. Therefore dev.39's catalog-level `type: 2` change did **not** reach MeshAgent as native `UserOnly` execution and still differed from the manually proven direct interactive PowerShell path.

Dev.40 marks only the trusted built-in `network-adapter-properties` command as `nativeUserSession`. The existing shared policy remains the single execution-policy owner and bypasses its script-oriented Scheduled Task wrapper only when this catalog-owned marker is present together with strict `runAsUser: 2`. The command therefore reaches MeshAgent directly as type-2/UserOnly. Route selection, `Status=Up`, IPv4/IPv6 fallback, deterministic metrics, `Namespace(49)` mapping and the actual `Properties/Właściwości` `FolderItemVerb.DoIt()` body remain unchanged. No new launcher, sleep, polling or fallback panel was added.

## Admin root cause / change

Modern MeshCentral changes the active Bootswatch/theme by updating the existing `#theme-stylesheet.href`. The Admin owner observed only parent `html/body` class and `data-bs-theme`, so a Modern color/theme change could complete without invoking SIRK synchronization. Dev.39 changed signal precedence but did not observe the actual stylesheet writer.

Dev.40 reuses the same single parent `MutationObserver` and adds the existing `#theme-stylesheet` `href` as a watched signal, plus its `load` event so synchronization runs after the new CSS is applied. When the Modern stylesheet exists, the effective computed parent body background participates before stale legacy `nightMode`; Classic `body.night` remains supported. Existing parent surface copy, form state, active section and F5 recovery are preserved. No second observer, polling, backend request or Admin rerender was added.
