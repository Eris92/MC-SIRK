# MC-SIRK 0.1.1-dev.26

Status: development pre-1.0. No tag or GitHub Release.

## Runtime included

- Continues Issue #177 after real `0.1.1-dev.25` MeshCentral smoke confirmed that the large deferred menu shift was removed but a small single left-menu flicker still remained after F5.
- Root cause: the permission-safe bootstrap could insert SIRK menu nodes before the current MeshCentral `goPageStart -> goPageEnd` redraw completed. The host could then replace the native left-bar DOM, removing those early nodes, and a later runtime/module reconcile recreated them once, producing the short blink.
- `public/shared/runtime.js` now reuses the existing native page lifecycle as the readiness gate: every `goPageStart` invalidates the previous page-ready state and bootstrap menu insertion waits for the current `goPageEnd`.
- `public/shared/core.js` adds the same owner-level safety boundary: an existing SIRK menu node may still be updated while the host page is changing, but a missing node is not created until native page completion. This also covers direct `module-shell` refresh calls without adding a second owner.
- Module scripts and renderers still load in the existing bounded parallel startup; the fix does not block module initialization on menu readiness.
- No polling, `MutationObserver`, readiness timer, placeholder menu, CSS masking, extra request or second menu renderer was added.
