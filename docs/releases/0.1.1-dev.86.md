# SIRK Management Platform 0.1.1-dev.86

Date: 2026-08-13
Status: development pre-1.0, real MeshCentral/Jira acceptance pending

## Scope

Remove the visible empty first paint of the `Sprzęt do protokołu` wizard step while preserving the selected-user equipment scope and native MeshCentral dialog.

## Root cause

The shared parameter dialog mounted and showed the native modal before its asynchronous equipment provider completed. The `assetmulti` host therefore briefly displayed an empty checkbox shell and was populated one paint later.

## Correction

- After the user step resolves, prefetch equipment with the selected Jira user values before opening the equipment step.
- Store the returned options on the copied wizard variable.
- Render static `assetmulti` options into the detached dialog content before the native modal is shown.
- Explicitly disable the dynamic provider for that already-prefetched step, avoiding a duplicate request.
- Preserve every other parameter dialog, Jira query/cache contract, selection validation and subsequent protocol step unchanged.

## Verification

- Wizard regression requires options to be fetched before `Sprzęt do protokołu` is opened.
- The visible equipment step must receive a complete static option set and a disabled dynamic provider.
- Shared parameter regression requires detached checklist initialization for prefetched `assetmulti` options.
- JavaScript syntax checks and existing shared dialog lifecycle regression pass.
- Full `npm test` required before integration.
