# 0.1.169 (2026-11-05)

Status: development build, not released. Request: the RDP signing certificate is autoenrolled on the server, but My Commands ran everything on the target PC (SYSTEM or user). Needed a mixed mode: run part on the server, then copy the file to the target PC.

- `server/modules/commands/index.js`: `# SirkServerStage: <My Scripts path>` header. After node rights are checked, `runServerStage` calls `context.serverStage.run` with JSON env (`SIRK_STAGE_VARIABLES_JSON`, `SIRK_STAGE_NODE_JSON`, `SIRK_STAGE_COMMAND_PATH`) and the command script's CA values (`MYSCRIPTS_CA_*`), then rebuilds the agent command with `$SirkStageFileName`, `$SirkStageFileBase64`, `$SirkStageOutput`. Stage failure stops the run before anything reaches the agent.
- `server/modules/automation/index.js`: `context.serverStage.run` accepts only internal (`_`) My Scripts with `# SirkStageFor: MyCommands`; runs through the existing executor queue with `skipSystemEnvironment` and `stageFile`.
- `server/core/server-script-executor.js`: `stageFile` option creates a workspace and returns exactly one file (safe name, 1 B–256 KB) as Base64; workspace always removed.
- `seed/MyScripts/CA/_Sign RDP file.ps1` (new, internal): builds and signs the .rdp on the server (thumbprint or template, diagnostics from 0.1.168). `seed/MyCommands/CA/Generate signed RDP file.ps1`: delivery only (file name and signature checked, Desktop of the interactive user).
- Verification: new `test/server-stage.test.js` (executor double on Linux), `test/ca-integration.test.js`, `test/windows-ca-rdp-smoke.ps1` (Windows CI), full `npm test`. No tag or release.
