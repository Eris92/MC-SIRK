# 0.1.173 (2026-11-13)

Status: development build, not released. Real Windows x64 MeshCentral GUI/UAC smoke for #460 is required before issue closure.

- Issue #460 follow-up: the previous `0.1.172` ODBC preset ran as PowerShell via the scheduled-task user-session launcher. Other working System GUI presets (CMD, Registry Editor, MMC) use the native MeshAgent `type: 1`, `runAsUser: 2` path. The previous implementation therefore did not match the proven execution contract.
- A Windows CI regression proved that `start "" /B /WAIT powershell.exe` can return success even when its child PowerShell command fails. Do not use CMD START to infer UAC status.
- `ODBC (32-bit)` now executes `powershell.exe -NoProfile -WindowStyle Hidden -Command ...` synchronously as the logged-on user through the same native MeshAgent interactive execution path as CMD. Only the server-owned catalog preset may carry `nativeInteractiveGui: true`; the shared existing policy recognizes this marker, and custom commands cannot set it through the API.
- The PowerShell helper checks `SysWOW64\odbcad32.exe`, requests UAC with `Start-Process -Verb RunAs`, and propagates missing EXE/UAC rejection/native error codes to existing Results without waiting for the ODBC GUI to close.
- Verification: `test/odbc-command-contract.test.js`, `test/logged-on-user-command-policy.test.js`, `test/windows-odbc-command-smoke.ps1`, full `npm test`, Windows CI. No new service, polling or GUI components. Physical UAC/token/session behavior remains to be validated on MeshCentral.
- No tag/GitHub Release. PR: https://github.com/Eris92/MC-SIRK/pull/463 .
