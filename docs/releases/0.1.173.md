# 0.1.173 (2026-11-13)

Status: development build. Physical Windows Server 2019/2022 MeshCentral acceptance for #462 remains pending.

- Added one Commands / System preset `sync-server-date-time` with PL/EN labels, description of clock-change impact, explicit confirmation, SYSTEM context and existing folder/device rights, Commands/Quick/visibility/Results/audit.
- The Node server resolves its own process/OS zone through `Intl.DateTimeFormat().resolvedOptions().timeZone`, maps a supported IANA/Windows ID to Windows using a static Unicode CLDR windowsZones map and captures UTC through `new Date()` only after node permission resolution, directly before agent dispatch. Unknown mappings, invalid times, spoofed variables and non-Windows agent IDs fail closed. No browser/client clock source is used.
- The Windows PowerShell 5.1 command validates Windows and administrative privilege, the installed Windows zone, and UTC syntax before change. It sets the time zone only when different and uses the Windows `SetSystemTime` API with UTC, avoiding DST fall-back ambiguity/double conversion. It skips clock writes inside a 2-second tolerance and validates actual UTC (5-second post-write read-back tolerance) and time zone.
- Results contains JSON with source/previous/requested/actual UTC/local/time zone, status (`success`, `already-current`, `failed`, `partial-failure`), error and change flags. Does not edit NTP, domain policy, peers or Windows Time service. It adjusts only for elapsed script execution, not network/queue delays; no NTP or end-to-end accuracy guarantee.
- Tests: `test/server-time-sync.test.js`, `test/windows-server-time-sync-smoke.ps1`, CI Windows parser and full npm test.
- No tag, no GitHub release. Issue: https://github.com/Eris92/MC-SIRK/issues/462 .
