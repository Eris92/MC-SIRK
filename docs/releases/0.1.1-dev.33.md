# 0.1.1-dev.33

Status: **development pre-1.0**. This revision is the focused follow-up to real MeshCentral `0.1.1-dev.32` smoke failures reported on 2026-08-09. It is not a product release and creates no tag or GitHub Release.

## Real dev.32 evidence

The following real-runtime results are the reason for this revision:

- **SIRK Admin theme/F5:** PASS — the previously repaired Admin light/dark and F5 recovery behavior was confirmed working and is not changed here.
- **Results View surface (#125):** FAIL — the `View` action still appeared without a visible native button background/surface. The previous primary-variant-only fix was therefore ineffective.
- **Commands / Plugins (#232):** FAIL — both top tabs were visibly selected for roughly one second when entering Commands, even though the final state later converged.
- **Network Settings (#128):** FAIL — execution was launched for the interactive Windows session but no adapter properties UI opened.

Issues #125, #232 and #128 remain open until this revision passes real re-smoke.

## Changes

### Results View — standard native secondary action surface

- The shared Results `View` action now uses the same standard secondary/native button semantic as ordinary shared actions instead of forcing a primary-only variant that remained transparent in the reported host theme.
- `MeshThemeAdapter.button(view, "secondary")` is applied synchronously when the View button is created, before first paint.
- Existing `MeshThemeAdapter.refresh()` remains the theme-reconciliation owner.
- No hardcoded background, color palette, new CSS class, observer, timer, polling loop or second button owner was added.
- Copy/Download remain secondary actions and the existing viewer lifecycle is unchanged.

### Commands / native Plugins — no asynchronous selected-state gap

- `createDeviceIntegration().open()` no longer leaves the transition `go(19) -> setTimeout(0) -> select Commands` exposed to a browser paint.
- After native `go(19)` may synchronously select Plugins, the existing owner immediately selects the registered Commands nested page and reconciles `style3sel/style3x` in the same JavaScript transition.
- The existing bounded reconcile remains recovery only; no new observer, polling loop, click owner or lifecycle layer was added.
- The lifecycle test now emulates real `go(19)` selecting native Plugins and asserts exactly-one-selected **before** any timer is flushed.

### Network Settings — correct Windows Network Connections folder

- Active adapter selection remains based on the preferred live default route, with IPv4 preferred and IPv6 fallback, deterministic route/interface metrics and stable `InterfaceIndex` mapping.
- The Shell enumeration target is corrected from `Namespace(3)` to `shell:ConnectionsFolder` before invoking the resolved connection's `properties` verb.
- Stable command IDs, labels, Favorites/overrides, interactive-user launcher and `Network Control` behavior are preserved.
- No fixed UI sleep, panel-only fallback, second launcher, polling or observer was added.
