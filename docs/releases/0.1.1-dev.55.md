# SIRK Management Platform 0.1.1-dev.55

## Jira Asset Protocol list-mode regression

Real `0.1.1-dev.54` smoke exposed an immediate My Scripts -> Jira Asset Protocol failure before the native wizard opened:

`Cannot set property type of #<HTMLSelectElement> which has only a getter`

The failure was in the shared native parameter-dialog owner. The Protocol step uses the existing `select` control in `listMode` so transfer/return renders as an exclusive radio list. `buildContent()` created a SELECT from the control kind and then the checklist branch attempted to convert that SELECT into hidden state with `control.type = "hidden"`. `HTMLSelectElement.type` is read-only.

`0.1.1-dev.55` selects the state-owner element before assigning input type. Every checklist-backed control (`listMode` and `assetmulti`) now owns state through a hidden INPUT, while ordinary select, user and asset controls retain SELECT ownership and custom users retain INPUT ownership. No second renderer, dialog framework, timer, polling loop or DOM repair layer was added.

A focused regression executes the shared pure control-element contract for `select + listMode`, `user + listMode`, `assetmulti`, ordinary select/asset/user and custom user paths. Existing Jira wizard and shared parameter-dialog coverage remains the integration guard.
