# 0.1.156 (2026-11-04)

Carries the CA integration and signed RDP command developed as 0.1.142 (PR #430) onto main after 0.1.155. Content below is unchanged from that branch.


Status: development build, not released. Issues #405 and #406 stay open until real smoke.

## Scope
- `server/core/integration-service.js`: `integrations.ca` (`config` validated as `host\\CA name` without control characters, `template`, `rdpSigningThumbprint` normalized to 40-hex SHA-1). `configured().ca` is true only when `config` is set.
- `server/core/script-admin-service.js`: `CA` system credential profile and `caVariables(path)`; throws when the profile is required but CA is not configured.
- `server/core/server-script-executor.js`: `MYSCRIPTS_CA_CONFIG`, `MYSCRIPTS_CA_TEMPLATE`, `MYSCRIPTS_RDP_SIGNING_THUMBPRINT` for My Scripts with the CA profile.
- `server/modules/commands/index.js`: My Commands inject CA variables next to existing secret values.
- `web/admin/integrations.js`: Certificate Authority (CA) section.
- Seeds: `seed/MyScripts/CA`, `seed/MyCommands/CA/Generate signed RDP file.ps1`.

## Security
- Only non-secret CA identifiers and a certificate thumbprint are distributed; private keys stay in `LocalMachine\\My`, rdpsign.exe is the system binary, no ExecutionPolicy Bypass and no hard-coded paths.
- The Desktop file is written only after rdpsign exit code, `signscope`/`signature` lines and target were verified.

## Tests
- `node test/ca-integration.test.js`
- Windows CI: `test/windows-ca-rdp-smoke.ps1` (host validation, RDP content, fail-closed thumbprint/certificate).
