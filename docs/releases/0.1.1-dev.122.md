## AD reset real-smoke correction and SMS UTF-8 transport

Real MeshCentral smoke on `0.1.1-dev.121` rejected the previous AD/SMS correction: the reset dialog showed `Assign the configured Jira integration to this script first.` instead of loading users, and delivered SMS text still contained mojibake for Polish characters.

Root cause / decisions:

- the `ad-users` option path added a redundant per-script Jira credential gate even though the canonical `jira-asset-service.js` already owns the Jira users cache and its server-side integration credentials; this blocked the reset selector before the cache/AD UPN intersection could run;
- the reset PowerShell script itself consumes AD and SMSAPI credentials only, so declaring a Jira system credential there created configuration coupling without an execution dependency;
- the generic Node SMS path sent UTF-8 form bytes but did not set SMSAPI `encoding=utf-8`, while the Windows PowerShell 5.1 AD helper set the SMSAPI parameter but did not explicitly declare the form-body charset.

Changes:

- keep `server/core/jira-asset-service.js` as the single Jira users-cache owner and `server/core/ad-directory-service.js` as the one bounded `Jira emailAddress -> AD UserPrincipalName` matching owner;
- remove only the redundant Jira system-credential assignment check from the `ad-users` option branch; AD authorization remains required and Jira protocol/cache/generic Jira option consumers retain their existing Jira credential boundaries;
- remove `SirkSystemCredential: Jira` from `Reset user password and SMS.ps1`; the script retains `AD` and `SMS` credentials;
- keep the shared local Search/list filtering contract and add no per-keystroke Jira/AD request, polling, observer, timer or second cache owner;
- make server-side SMS sends include SMSAPI `encoding=utf-8` while retaining `application/x-www-form-urlencoded; charset=UTF-8`;
- make the shared Windows PowerShell AD SMS helper retain `encoding='utf-8'` and explicitly send the form as `application/x-www-form-urlencoded; charset=UTF-8` so Polish message text is encoded consistently under Windows PowerShell 5.1;
- preserve account reset/unlock, AD mobile lookup, `ChangePasswordAtLogon`, account creation OU allowlist, cryptographic password generation and the no-login/no-UPN SMS wording.

Verification:

- `test/sms-ad-workflows.test.js` covers a Polish message fixture (`Zażółć gęślą jaźń`), SMSAPI UTF-8 parameter/charset, server-owned Jira-cache reuse, case-insensitive UPN matching, AD-safe values, local Search metadata and the corrected credential boundary;
- existing localization, integration, security, Jira cache/protocol and requester confirmation/cancellation regressions remain required;
- full `npm test` and Windows interactive-shell smoke are required on the exact `0.1.1-dev.122` PR head before merge.

No tag or GitHub Release is created for this development revision. Issue #382 remains evidence-gated until real MeshCentral + SMSAPI re-smoke confirms the user list and received Polish SMS text.
