# SIRK Management Platform 0.1.1-dev.65

## Jira complete users and assigned Assets correction

Real `0.1.1-dev.64` smoke exposed two stale/scope problems in the Jira Asset Protocol path:

- a still-fresh legacy Jira users cache could preserve an older 1000-account snapshot even though the current provider can paginate further;
- the canonical Jira protocol and explicit Assets cache still sourced only `objectTypeAndChildren("Sprzęt użytkownika")`, so assets assigned to the user outside that object-type hierarchy were never available to the server-side user binding.

`0.1.1-dev.65` invalidates the legacy user-cache schema once and repopulates it through the existing bounded paginated owner. The canonical protocol and Jira Assets cache now use workspace-wide `Key is not EMPTY`, keep the existing authoritative Jira-user attribute match, raise the protocol selector only to the existing 5000-option ceiling, and keep the full shared snapshot scan bounded at 50,000 objects.

No Jira credential handling, browser AQL authority, polling lifecycle or cache owner was added.
