# 0.1.133

## Scope

- Make scripts under the canonical `Entra ID` My Scripts namespace use the global Entra/AAD integration instead of requiring duplicate per-script tenant/client credentials.
- Reuse `integration-service.js`, `script-admin-service.js` and `server-script-executor.js`; no new credential store or integration owner is introduced.
- Treat the Entra namespace and explicit `SirkSystemCredential: Entra` metadata as a required system profile.
- Inject configured `tenantId`, `clientId` and `clientSecret` only at execution time through `MYSCRIPTS_ENTRA_*` and compatible declared PowerShell variables such as `TenantId`, `ClientId`, `ClientSecret`, `AppId` and `AppSecret`.
- Hide Entra-backed secret variables from per-script credential configuration and ignore stale per-script copies for those mapped values.
- Fail closed before child-process spawn when the global Entra integration is incomplete; preserve existing credential behavior outside Entra scripts.

## Verification

- Targeted regression covers an `Entra ID/druk/Sprawdzanie_licencji.ps1` definition with required tenant/client/secret variables and no per-script secret store.
- Regression verifies exact global values in both PowerShell variables and `MYSCRIPTS_ENTRA_*`, fail-closed incomplete integration behavior, and unchanged local-secret requirements for non-Entra scripts.
- Full `npm test` required because the shared My Scripts credential/runtime contract changes.
