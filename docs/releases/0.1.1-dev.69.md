# SIRK Management Platform 0.1.1-dev.69

## Isolated Windows admin settings tests

On a Windows host with an existing `%PROGRAMDATA%\SIRK Management Platform\settings.json`, the runtime-backed admin tests selected that legacy fallback instead of their temporary MeshCentral `datapath`. The suite could therefore fail with `ENOENT` for the expected temporary settings file and could touch unrelated persisted settings.

`0.1.1-dev.69` adds an explicit `fallbackDataRoot` injection seam to the runtime. Production behavior remains unchanged by default. Runtime-backed admin tests pass an empty fallback root so settings and approval state stay inside their owned temporary directory.

The icon-mode authorization, permissions persistence and restart-persistence tests now remain deterministic on Windows without changing Execution Policy or relying on machine state.
