## Nessus vulnerability dataset (#422)

- Owner: `server/core/vulnerability-service.js`, utworzony w `runtime.js` jako `context.vulnerabilities`.
- Źródło: plik CSV eksportera (`ScanNessusAPI_updated.py`) kopiowany przez harmonogram zadań do `meshcentral-data/sirk-platform-data/nessus/inbox/` (dowolna nazwa `*.csv`; brany jest najnowszy plik). Plik zmodyfikowany < 3 s temu jest pomijany do następnego odczytu, aby nie czytać kopiowania w toku.
- Import jest leniwy: przy odczycie najwyżej raz na 5 s wykonywany jest `stat` katalogu; parsowanie tylko przy zmianie sygnatury (nazwa/rozmiar/mtime), identyczna treść (SHA-256) nie przebudowuje snapshotu. Brak timerów i pollingu.
- Walidacja: UTF-8 (BOM opcjonalny), `;`, cytowanie RFC4180, dokładne 17 nagłówków, liczba pól w każdym wierszu, numeryczny `Plugin ID`, limity (64 MB, 300 000 wierszy, 4000 znaków/komórkę, 50 000 hostów). Każdy błąd odrzuca cały plik; ostatni poprawny snapshot (`nessus/snapshot.json`, zapis tmp + rename) pozostaje aktywny, a `lastError` jest widoczny w statusie.
- Model: per host tylko najnowsza `Generation Date` (dalej `History ID`, `Week`), `Plugin ID=0` = brak wykryć, identyczne wiersze append liczone jako `occurrences`, liczniki Critical/High/Medium/Low/Info, stan `not_imported` / `error` / `host_unmatched` / `ambiguous` / `stale` (>14 dni lub niepoprawna data) / `no_findings` / `available`.
- Dopasowanie hosta: serwer rozwiązuje urządzenie przez `GetNodeWithRights` (bez wymogu Site Admin) i porównuje `rname`/`name`/`host` z `Host`, potem `Host Original`, potem short name — bez substringów; kilka kandydatów = `ambiguous`.
- API (moduł Commands): `GET mycommands/vulnerabilities?nodeId=…[&detail=1]`, `GET mycommands/vulnerabilities-status` (Site Admin; pokazuje ścieżkę inbox i ostatni import).
- Zdarzenia: `sirk-vulnerabilities-import` (success/rejected) z liczbą rekordów, hostów i SHA-256, bez treści CSV.

## Commands → Podatności (#423)

Pozycja pod „Wyniki”: summary hosta, status świeżości, liczniki, filtry ryzyka (lewa kolumna), Exploit i tekst, sortowanie ważność/score, paginacja po 100, szczegóły 17 pól w natywnym oknie. Pobieranie przy wejściu i na Refresh; odpowiedź poprzedniego hosta jest odrzucana.

## Quick / Desktop (#424)

Jeden odczyt summary na nową sesję Desktop; alert tylko dla statusu `available` z findings Critical–Low. Zamknięcie dotyczy bieżącej sesji; ponowne połączenie ostrzega ponownie. Hook `onDesktopDisconnect` usuwa alert. Lista w Quick pobiera detale dopiero po otwarciu.

## My Scripts → Security / Nessus - All Hosts (#425)

Edytowalny skrypt z nagłówkiem `# SirkDataFeed: Nessus`. Executor przekazuje wyłącznie ścieżkę snapshotu (`SIRK_NESSUS_SNAPSHOT`); dostęp wymaga Site Admin przy request i przed wykonaniem; CSV (`;`, UTF-8 BOM, ochrona formuł, 17 kolumn + status) w `_siteadmin-reports` jest pobieralny tylko przez Site Admin; pliki starsze niż 7 dni są usuwane przy kolejnym uruchomieniu.
