# 0.1.134

## Scope

- Allow native Desktop Quick direct executions to run concurrently on the same device instead of being rejected by the historical per-agent `SIRK_AGENT_COMMAND_BUSY` guard.
- Keep the existing per-node in-flight guard unchanged for ordinary Commands, approval and multi-device execution paths.
- Scope the Quick bypass with Node `AsyncLocalStorage` inside the existing `agent-command-guard.js` owner, so concurrent unrelated requests cannot inherit the bypass.
- Preserve unique `responseid` correlation, output capture and terminal/failure lock release behavior.
- Do not add a timer, queue, polling loop or a second command-execution owner.

## Verification

- `test/agent-command-guard.test.js` covers two concurrent Quick direct launches on a node that already has a guarded command, confirms the guarded lock remains intact, verifies ordinary commands are still rejected, and confirms no internal bypass field is added to the MeshAgent command object.
- Full `npm test` required because the shared command-execution runtime policy changes.

Issue #411 remains open until real MeshCentral Quick smoke confirms several consecutive launches on one device are accepted without `SIRK_AGENT_COMMAND_BUSY`.
