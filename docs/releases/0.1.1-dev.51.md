Date: 2026-08-11

## Jira cache / internal My Scripts / credentials UX

Real Jira setup feedback clarified three ownership contracts.

- Jira users remain owned by the existing server-side `jira-asset-service`: a fresh cache is reused for 24 hours, an expired cache is refreshed before a user-bound Assets query, and the previous cache is used only as stale fallback when Jira refresh fails. The Jira token is never persisted in the cache. No duplicate PowerShell cache runner or polling loop was added.
- `_shared` is reserved for reusable internal My Scripts content. Any underscore-prefixed path segment is removed from the public script tree and rejected by public My Scripts script/source/definition/credentials/options/request execution paths.
- Jira Asset Protocol declares `SirkSystemCredential: Jira`. In My Scripts Edit mode the Credentials key remains visible for every editable script: enabled for local or declared system credential consumers, disabled/grey when unused, without per-row backend requests.

Verification includes targeted stale-cache-before-Assets coverage, internal-path/credential-action contract coverage and the complete repository test suite.

Issues #294 and #290 remain open for real Jira + MeshCentral smoke evidence.
