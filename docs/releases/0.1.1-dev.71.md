# SIRK Management Platform 0.1.1-dev.71

Date: 2026-08-12  
Status: development build, no product release

## Summary

Real test-environment validation exposed a second Assets-cache bottleneck after the Jira attribute-metadata fix: the workspace-wide snapshot persisted 5000 raw Jira objects as a 269 MB JSON file. A forced refresh completed only after roughly 2.5 minutes while the MeshCentral Node process held about 1.1 GB of memory.

`0.1.1-dev.71` introduces cache schema v3. It stores only the object identifiers, type, label values and normalized assignment identities required by the user-bound equipment selector and protocol. Legacy cache files are checked through a bounded header read, so a v1/v2 snapshot is invalidated without parsing hundreds of megabytes into the service process.

The cache remains a single 24-hour workspace-wide snapshot shared by all Jira users. A regression test verifies heterogeneous assigned objects, rejects unrelated identity text, preserves protocol-facing fields and asserts that the persisted representation no longer contains raw nested `objectAttributeValues`.

## Deployment note

The plugin backend must be loaded in a fresh MeshCentral service process before the v3 cache behavior can be observed. The test environment currently has the `0.1.1-dev.70` package installed, but its long-lived process still holds the earlier Jira service modules until an explicitly authorized service restart.
