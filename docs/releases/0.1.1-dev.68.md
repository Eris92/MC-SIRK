# SIRK Management Platform 0.1.1-dev.68

## Jira protocol renderer-owned PDF fallback

Real `0.1.1-dev.67` smoke still returned the raw Edge headless failure in Results, so the protocol-service fallback did not protect the real runtime path.

`0.1.1-dev.68` moves the bounded direct PDF fallback into `server/core/html-pdf-renderer.js`, the same owner that produces the Edge failure. `server/core/jira-protocol-service.js` now delegates PDF generation exactly once and supplies the canonical protocol text as `fallbackText`. After both bounded Edge modes fail, the renderer returns dependency-free direct PDF bytes instead of bubbling the Edge-only error. The protocol service still validates `%PDF-1.` before persisting the protected artifact.

No `--no-sandbox`, external PDF dependency, polling loop, persistent browser profile or second protocol lifecycle owner was added.
