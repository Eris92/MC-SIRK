## Rules contract (`sirk-platform-data/nessus/rules.json`)
```json
{ "schema": 1, "rules": [
  { "action": "exclude", "pluginId": "2001", "host": "pc01*", "reason": "Legacy Java required by ERP", "expires": "2026-12-31", "enabled": true },
  { "action": "remediate", "name": "Google Chrome <", "nameMode": "contains", "scriptPath": "Software/Update Chrome.ps1" }
] }
```
- `action`: `exclude` or `remediate`; `pluginId` (digits) and/or `name` (`contains`/`exact`, case-insensitive) are required; `host` is an optional pattern (letters, digits, `.-_`, `*`) matched against the Nessus host, original host and short names.
- `remediate` needs `scriptPath` of a My Commands script (validated when saved from the portal). Max 500 rules, file max 1 MB; a plain array is accepted for hand-written files.
- Expired (`expires` < today) or disabled rules are ignored. Exclusion wins over remediation.
- Rules are applied when data is read (`server/core/vulnerability-service.js`), so changes need no re-import. A stat per read reloads a changed file. An invalid file applies no rules and is reported in settings.
- API: `GET/POST mycommands/vulnerability-rules` (Site Admin), settings tab `web/admin/vulnerabilities.js`. Saving writes atomically and dispatches a MeshCentral event with counts only.
