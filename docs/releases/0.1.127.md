# SIRK Management Platform 0.1.127

**Status:** development pre-1.0  
**Date:** 2026-08-19

## Evidence

Real Issue #382 feedback after `0.1.126` remained unchanged. The deployment/runtime proof therefore did not resolve the remaining AD reset selector / received-SMS acceptance by itself.

Current source inspection exposed a separate My Scripts ownership defect: `server/core/automation-root.js` could load metadata and dynamic-option headers from persistent `sirk-platform-data` script trees, while `server/core/server-script-executor.js` always executes `pluginRoot/seed/MyScripts`. A stale persistent copy could therefore keep older selector metadata visible while a different bundled script was executed.

## Changes

- Make `server/core/automation-root.js` resolve bundled My Scripts only from `pluginRoot/seed/MyScripts`, matching the existing execution and `MYSCRIPTS_SCRIPTS_ROOT` paths.
- Stop persistent `sirk-platform-data/myscripts/scripts` and `sirk-platform-data/scripts/MyScripts` directories from shadowing bundled metadata/tree/dynamic-option definitions.
- Do not delete or modify legacy persistent script directories; they are simply no longer runtime source owners.
- Add a regression that creates stale persistent reset-script copies and proves the current bundled `ad-users` + local Search metadata still wins while the legacy files remain untouched.
- Preserve the current bounded DirectoryServices AD selector bridge and ASCII-safe percent-encoded SMS UTF-8 transport unchanged.

## Verification target

- `node test/myscripts-source-ownership.test.js`
- `node test/sms-ad-workflows.test.js`
- full `npm test`
- existing Windows installer parser, Network, SMS UTF-8 and AD selector bridge smokes in CI
