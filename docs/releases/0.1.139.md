# SIRK Management Platform 0.1.139

## Quick direct command concurrency (#411)

Real MeshCentral smoke of 0.1.134 continued to return `SIRK_AGENT_COMMAND_BUSY` on the second Quick command on the same device. The AsyncLocalStorage-only bypass was not reliable across the actual resolved-device callback chain.

- The My Commands execution owner now explicitly tags the rights-checked, server-resolved node context for a native Desktop Quick direct execution. The marker is a nonenumerable, nonserializable Symbol property.
- `agent-command-guard.js` checks only this server-owned execution context. It does not wrap `apiPost`, track async-local state or relax the ordinary per-node command guard.
- Ordinary Commands, approval and multi-device executions remain guarded. Existing in-flight ordinary locks are not cleared by Quick; result correlation and terminal cleanup are unchanged.
- The internal marker is never part of the MeshAgent `runcommands` payload.
- The regression test follows the asynchronous `resolveNode` boundary and checks the isolated direct flag and ordinary command semantics.

## Verification requirements

- Targeted: `node test/agent-command-guard.test.js`.
- Full: `npm test` and Windows GitHub Actions smoke before merge.
- Real MeshCentral acceptance: overlapping Quick launches on the same Desktop node while an ordinary guarded command is active. Issue #411 remains open until this passes.
