# 0.1.157 (2026-11-04)

Carries the CSR signing workflow developed as 0.1.143 (PR #431) onto main after 0.1.156. Content below is unchanged from that branch.

Status: development build, not released. Issue #407 stays open until a real Enterprise CA smoke. Builds on 0.1.142 (#405 CA integration).

## Contract
- Script header: `# VariableFileRequiredPL/EN: $CsrFile=csr, Label | Description`. The value after `=` is the server-validated format; only `csr` exists. File inputs have no default value.
- Browser: `public/shared/ui/parameter-dialog.js` renders `<input type=file>` (single file, `accept` hint, 32 KB). `public/modules/automation/index.js` reads it with `FileReader` only on submit and posts `files: { Name: { name, data(base64) } }` next to `variableValues`.
- Server (`server/modules/automation/index.js`): rejects unexpected file keys, arrays/multiple files, names with path separators/control characters/NUL, oversized or invalid base64, and anything that is not a valid CSR (`server/core/csr-service.js`) before staging. The client file name and MIME type are not used. The variable value is overwritten with a staging token.
- Staging (`server/core/artifact-service.js`): `artifacts/upload-<48 hex>/` with `input.bin` (0600) and `upload.json` binding owner, script and variable; same 24 h retention as request artifacts. Request IDs cannot address staging or workspace directories.
- Executor (`server/core/server-script-executor.js`): resolves the token for the requester, re-validates the CSR, sets the variable to the staged path and `MYSCRIPTS_OUTPUT_DIR` to a private `work-<32 hex>` directory. After exit 0 exactly one `.cer`/`.crt` is accepted, verified (public key == CSR key, issuer `CN` == CA name from `host\CA name`) and stored as a `certificate` artifact (`application/pkix-cert`, always `attachment`). Upload and workspace are removed in every path.
- Download: existing `admin.js?action=download&requestId&artifactId`, authorized by `context.approval.getRequest(user, requestId)`.

## Script
`seed/MyScripts/CA/Sign CSR.ps1` runs `certreq.exe -submit -q -config <CA> -attrib CertificateTemplate:<template>` with separate arguments, as the MeshCentral service identity (that account needs Enroll permission on the template). Pending/denied/error answers throw; the CSR body is never printed. AD-identity execution is not used.
