# SIRK Management Platform 0.1.1-dev.66

## Jira assignment binding and Edge PDF compatibility correction

Real `0.1.1-dev.65` smoke exposed two remaining acceptance failures:

- after widening Jira Assets to workspace scope, the server-side matcher could return the selected Jira `Users` identity object itself because it scanned every primitive attribute string;
- Microsoft Edge still exited before creating `protocol.pdf` even with an isolated writable per-render profile, and returned no useful browser stderr in the observed failure.

`0.1.1-dev.66` keeps the workspace-wide snapshot but narrows user binding to explicit Jira user/object references plus bounded assignment-semantic attributes, and rejects an object whose own label is the selected Jira identity. This preserves heterogeneous assigned assets without treating arbitrary identity text or the `Users` object itself as equipment.

For styled PDF generation, the existing renderer keeps the isolated temporary profile and sandbox. Edge now prefers the generic `--headless` print path with portable forward-slash profile/output paths, then performs exactly one bounded retry with `--headless=new`; both failures retain bounded diagnostics. No `--no-sandbox`, persistent profile, polling loop or external PDF dependency was added.
