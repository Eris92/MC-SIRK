# SIRK Management Platform 0.1.129

**Status:** development pre-1.0  
**Date:** 2026-08-19

## Evidence

Real Issue #382 smoke after merged `0.1.128` showed the current reset dialog metadata (`Search`, `User`) but an empty user checklist. The previous deployment/source/DirectoryServices corrections therefore did not satisfy selector acceptance.

Current source still made dialog opening wait for an eager live AD intersection of the whole Jira user cache. A successful zero-match result was returned as an empty array, so the native parameter dialog had nothing to render even when Jira itself already had users.

## Changes

- Make the reset user option path cache-first: `ad-directory-service.js` returns deduplicated Jira-cache identities with a usable `emailAddress`/UPN without a live AD query on dialog open.
- Keep the existing 24h Jira user cache owner and local shared Search; no new cache, polling, timer, observer or per-search backend request.
- Exclude cache entries without a usable UPN/e-mail and fail with a short explicit error if no selectable identity exists instead of silently rendering an empty checklist.
- Change `Reset user password and SMS.ps1` so the selected value is the Jira UPN; validate it and resolve only that one identity by exact AD `UserPrincipalName` immediately before the password mutation.
- Fail closed unless the selected UPN resolves to exactly one AD account; keep reset, unlock, `ChangePasswordAtLogon`, mobile lookup, password generation and SMS behavior unchanged.
- Preserve the maintained `System.DirectoryServices` bridge as bounded fallback/internal AD functionality; it is no longer in the normal reset-dialog hot path.
- Preserve the `0.1.128` ASCII-safe AD account SMS wording and the existing SMSAPI transport unchanged.
