# MC-SIRK 0.1.1-dev.25

Status: development pre-1.0. No tag or GitHub Release.

## Runtime included

- Continues Issues #121 and #177 after real `0.1.1-dev.24` MeshCentral smoke showed two remaining left-menu problems: SIRK artwork was visibly smaller than native Devices, and the left menu still shifted more than the already-stable Move Request action after F5.
- Root cause: permission-safe `core.ensureMenu()` mounted the menu early, but deferred `public/shared/ui/page.js` still installed a second native left-menu wrapper. In Classic it re-cloned `.lbtg`, changed icon geometry, reset classes/selection and therefore caused a visible second presentation pass.
- `public/shared/core.js` now owns final first-paint left-menu classes, active state, icon family/source and icon geometry; `public/shared/ui/page.js` no longer wraps or normalizes the left menu later.
- Classic family uses white/native-style artwork and keeps the host `.lbtg` class structure with a 48 px drawing size from the first mount.
- Modern family remains colored, uses a larger 32 px image box and tighter SVG viewBoxes so visible artwork is closer to native icon scale.
- Repeated menu reconciliation reuses the same menu/icon nodes, preserves active selection and avoids redundant ordered `insertBefore()` calls when entries are already in place.
- Existing `Auto` / `Classic` / `Modern` setting remains the only icon policy; no fourth mode, CSS filter, polling, MutationObserver, timer, second renderer or extra request was added.
