## Jira Asset Protocol participant labels

Real generated-PDF feedback on dev.118 exposed a participant-label mismatch: receive/return direction changed the labels under the protocol while the rendered names remained in the fixed `user` / `itPerson` slots.

Root cause:

- the protocol renderer dynamically labelled the two participant cards as giving/receiving parties based on asset actions;
- the actual card values were still rendered in the fixed order `user.name`, then `itPerson.name`;
- equipment direction is already represented explicitly by `Przyjęcie sprzętu` / `Zdanie sprzętu` in the changes table, so repeating direction in participant identity labels added ambiguity without new information.

Changes:

- always render participant cards in the fixed order `Użytkownik`, then `Przedstawiciel IT`;
- replace current Jira Asset Protocol `Osoba IT` wording with `Przedstawiciel IT` in PDF metadata, raw/debug output and the My Scripts protocol field;
- apply the same fixed participant identity order to the legacy renderer fallback;
- keep generic signature captions as `Podpis` instead of inferring giver/receiver roles;
- preserve the operation table as the owner of equipment receive/return direction;
- preserve the dev.118 centered title, dev.117 72px signature area, protected PDF lifecycle, requester confirmation and Jira CMDB semantics;
- add no new CSS class, renderer, lifecycle owner, timer, observer or request.

Verification:

- `test/jira-protocol-participant-labels.test.js` covers receive, return, reconciliation and legacy paths and rejects the old direction-dependent labels;
- the full repository suite and Windows interactive-shell smoke are required on the exact versioned PR head before merge.

No tag or GitHub Release is created for this development revision.
