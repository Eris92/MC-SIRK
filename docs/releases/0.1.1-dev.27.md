# MC-SIRK 0.1.1-dev.27

Status: development pre-1.0. No tag or GitHub Release.

## Runtime included

- Continues Issue #177 after real `0.1.1-dev.26` MeshCentral smoke confirmed that a small left-menu flicker still remained after Refresh.
- Root cause: one native `goPageEnd` could reconcile bootstrap surfaces and then invoke module `onNativePageEnd -> refreshMenu`, so `core.ensureMenu()` ran repeatedly for the same entries. Although nodes were reused, every pass rewrote classes, active state, icon family, source and geometry, allowing repaint/reflow churn.
- `public/shared/core.js` remains the single menu/icon owner and now applies visible state only when the effective value changes.
- Existing menu and icon nodes, handlers, active state, ordering, permission-safe bootstrap and native page-ready creation remain intact.
- No polling, `MutationObserver`, timer, placeholder, CSS masking, extra request or second menu renderer was added.

## Verification

- Classic and Modern targeted regressions require repeated reconciliation to perform zero writes to visible class, icon family, source and geometry state.
- Parser and targeted startup/menu/icon-mode tests: GREEN.
- Full canonical `npm test` in a clean LF checkout with the exact worktree diff: GREEN.
- Real local Modern MeshCentral smoke: hard Refresh x5 kept one node per enabled entry with stable family/source/class/box; an 800 ms raw-pixel comparison of the icon region reported zero changed channels.
- Real local Classic MeshCentral smoke through `?sitestyle=1`: five consecutive fresh navigations kept one node per enabled entry, the `classic` icon family and identical class/source/geometry state after 800 ms.
- Devices -> SIRK -> Devices -> hard Refresh preserved unique menu entries and active-state lifecycle; light and dark smoke produced no startup console errors.
