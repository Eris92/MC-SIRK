# SIRK Management Platform 0.1.130

**Status:** development pre-1.0  
**Date:** 2026-08-19

## Evidence

Real Issue #397 smoke on `0.1.129` showed the Entra ID license report producing a growing sequence of timestamped CSV files from one visible action while Results accumulated repeated report/count messages. The visible `Download CSV` action did not yield a usable download.

## Root cause / decision

- The My Scripts browser submit owner had no per-script in-flight guard for buttonless `executeOnSelect` paths. Repeated UI callbacks could therefore enqueue duplicate `request` POSTs while the previous execution was still active; the existing server executor serializes script work, matching the observed one-new-file-every-few-seconds pattern.
- Shared Results retained the first `CSV_DOWNLOAD:` marker from accumulated output, so a result containing several markers could point the button at a stale report.
- The CSV action assigned `window.location.href` to the attachment endpoint, coupling a file download to navigation of the MeshCentral SPA.

## Changes

- Reuse the existing My Scripts browser state for one single-flight operation per script path. Duplicate submit attempts while an operation is active reuse the same Promise and cannot emit another backend POST.
- Release the in-flight entry on both resolved and rejected completion so an explicit later run remains possible.
- Make the last valid `CSV_DOWNLOAD:` marker authoritative for accumulated output.
- Start CSV download through a transient same-origin anchor while preserving the existing authenticated `asset=download` endpoint.
- Keep the server-side canonical-root allowlist, `.csv` restriction, attachment headers and `nosniff` protection unchanged.
- Add no cache, timer, observer, polling loop or additional request owner.
