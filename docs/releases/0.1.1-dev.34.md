Status: **development pre-1.0**. This revision is the focused follow-up to real MeshCentral `0.1.1-dev.33` smoke failures reported on 2026-08-09. It is not a product release and creates no tag or GitHub Release.

## Real dev.33 evidence

- **Results viewer surface (#237):** FAIL — the opened `Request details` viewer was transparent and the underlying Move Requests table remained visible through its body. This was separated from #125 because the button and the viewer have different owners.

Issues #128 and #237 remain open until this revision passes real re-smoke.

## Changes

### Results viewer — native MeshCentral dialog surface

- `public/shared/ui/results.js::openViewer()` no longer constructs the plugin-owned `.mc-results-viewer-overlay` modal tree that produced the transparent body.
- Modern MeshCentral uses the host `setModalContent("xxAddAgent", ...)` + `showModal("xxAddAgentModal")` lifecycle with an extra-large native modal.
- Classic MeshCentral uses the host `setDialogMode(2, ..., 1, ...)` lifecycle, where button mask `1` is the native OK/close action.
- The host creates the outer modal surface; SIRK then reacquires a fixed `SirkResultsViewerNativeHost` placeholder and mounts the existing canonical result renderer into it as live DOM.
- Copy, generated CSV Download, structured results, filtering and Debug/raw output remain owned by `appendResult()` and retain live handlers.
- Dynamic dialog titles are HTML-escaped before entering the host HTML dialog API.
- No private light/dark background palette, replacement modal framework, observer, polling loop or timer staircase was added.

### Network Settings — corrected Shell namespace and hidden helper launch

- Active adapter selection still uses the preferred live default route, IPv4 first with IPv6 fallback, deterministic route/interface metric sorting and stable `InterfaceIndex` mapping.
- The ineffective dev.33 `Shell.Application.NameSpace('shell:ConnectionsFolder')` input is removed.
- Network Connections enumeration now uses the Connections CSIDL value `0x31` / decimal `49` before invoking the resolved connection's `properties` verb.
- The existing logged-on-user launcher now derives VBS `shell.Run` window style from explicit PowerShell `-WindowStyle Hidden` instead of always forcing visible style `1`.
- Hidden helper commands launch with style `0` and immediately leave the VBS focus loop; normal interactive PowerShell/CMD/MMC commands retain their existing visible/focus behavior.
- No panel-only fallback, second launcher, polling loop or fixed UI sleep was added.
