# SIRK Management Platform 0.1.1-dev.107

Date: 2026-08-13
Status: development pre-1.0, real MeshCentral/Jira acceptance pending

## Scope

Restore the bounded Jira Assets pipeline that was removed by the dev.82 full-tree rollback, while keeping every post-dev.82 UI, PDF, scheduler, SMTP and AD change on current `main`.

## Root cause

The installed/current dev.106 code still used the dev.63 `server/core/jira-asset-service.js`. Commit dev.82 intentionally restored the full dev.63 tree and explicitly reverted the dev.64-dev.81 Jira matching, cache and pagination work; no later commit modified this service.

The strongest real-tenant evidence remains the dev.81 cache capture: Jira returned a snapshot capped at exactly 1000 raw objects (540 `Komputer`, only 1 `Monitor` despite 181 monitors in the schema tree). That cached monitor already matched the selected user through `Osoba_odpowiedzialna`, proving the heterogeneous assignment matcher was not the limiting stage. Jira's AQL response reported a capped `totalFilterCount` while `hasMoreResults` remained true.

## Changes

- Restore the dev.81 Jira Assets service on top of current main only; do not restore the old tree.
- Keep `objectType in objectTypeAndChildren("Sprzęt użytkownika")` unchanged in both protocol and cache scripts.
- Restore user cache schema v2 so legacy 1000-user snapshots are invalidated and repopulated by pagination.
- Restore compact Assets cache schema v4, response attribute-name binding, explicit user/reference matching, `Osoba_odpowiedzialna` plain-value support and identity-object aliases.
- Restore a 100-page/50k-object safety bound, three-request page concurrency and a 180-second refresh bound.
- Continue paging past a capped Jira total while the last fetched page still reports more results.
- Restore targeted regressions for capped totals, responsible-person assignment, compact reference cache behavior and bounded concurrent refresh.
