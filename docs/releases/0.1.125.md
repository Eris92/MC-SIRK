# SIRK Management Platform 0.1.125

Status: development pre-1.0. This is not a product release.

## Version contract

Real MeshCentral smoke for Issue #382 exposed that the previous `0.1.1-dev.X` scheme is unsuitable for native plugin update detection: current MeshCentral comparison removes the `-...` suffix before comparing versions. Starting with revision 125, MC-SIRK uses increasing three-part numeric SemVer `0.1.X`; the third segment is the development revision. `0.1.125` remains below `1.0.0`.

The exact pre-migration `changelog.md` and `version-history.json` are preserved as `docs/releases/changelog-through-0.1.1-dev.124.md` and `docs/releases/version-history-through-0.1.1-dev.124.json`. Current metadata keeps the active numeric revision plus the recent failed-smoke chain, while `docs/releases/README.md` remains the per-revision historical index.

## Runtime update correction

- `SIRKPortal.js` reads the current on-disk `config.json` version on every plugin instantiation.
- Same-version reinstantiation reuses the loaded implementation.
- A changed version clears only MC-SIRK internal Node module cache entries, keeps the stable entrypoint, and reloads the implementation and existing policy modules.
- Modules outside the plugin root are not touched; MeshCentral core is not modified.

## First activation

An already running process that loaded the pre-0.1.125 entrypoint cannot execute logic added later. The first installation of `0.1.125` therefore requires the normal backend restart performed by the maintained installer, or an equivalent verified MeshCentral service restart.
