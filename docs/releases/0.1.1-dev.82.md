# SIRK Management Platform 0.1.1-dev.82

Date: 2026-08-13
Status: development pre-1.0, real MeshCentral/Jira acceptance pending — explicit user-directed rollback

## Scope

The user asked to stop iterating on dev.66-dev.81's matching/pagination corrections and instead restore the exact `0.1.1-dev.63` (2026-08-11) codebase as the new current baseline, since that is the last real-smoke-confirmed version where `Sprzęt do protokołu` returned every equipment type for a selected user. The user explicitly accepted this over further targeted fixes.

## What this reverts

This is a full-tree restore of the `0.1.1-dev.63` state (commit `e127278`) on top of current `main`, only bumping the version number and refreshing changelog/docs metadata. Concretely, this reintroduces dev.63's behavior and **removes** everything shipped between dev.64 and dev.81:

- **Jira Assets matching (`entryMatchesUser`)** reverts to the permissive dev.63 contract: a selected user's identity is matched against *any* attribute text on an equipment object, with no attribute-name gating and no structured-reference requirement. This is the behavior the user confirmed shows every equipment type. It also reopens the false-positive class `0.1.1-dev.66` was written to close (unrelated plain text that happens to contain a matching substring could bind to the wrong user).
- **Jira Assets pagination** loses the `0.1.1-dev.81` fix for a Jira-capped `totalFilterCount`; dev.63 pages using the older, simpler total-bound logic.
- **Jira Assets cache** reverts from compact schema v4 (dev.71/dev.72, small persisted snapshots with only match-relevant fields) to the dev.63 raw-payload cache, which is known to grow to hundreds of MB for large workspaces.
- **Jira users cache** reverts from schema v2 (dev.65, paginates past 1,000 accounts) to the dev.63 1,000-account cutoff.
- **PDF rendering** reverts from the dev.64 isolated writable browser profile, the dev.66-68 bounded Edge headless retry + dependency-free plain-text fallback, and the dev.80 fallback-reason diagnostic, back to dev.63's single unguarded `--headless=new` attempt with no fallback — real dev.63/dev.65/dev.66 smoke found this failed to produce a usable `protocol.pdf` under the MeshCentral Windows service context.
- Removes the `0.1.1-dev.64` through `0.1.1-dev.75` and `0.1.1-dev.79`-`0.1.1-dev.81` release-notes files and their regression tests, since they document/verify behavior no longer present.

## Why

Every targeted fix attempted since dev.66 (narrower assignment-attribute matching, identity-object bridging, a Jira-capped-total pagination fix) either left equipment scope incomplete in real smoke or could not be validated without data the user could not easily extract. The user chose to accept dev.63's known trade-offs (broader matching, larger cache, no PDF fallback) in exchange for the equipment list actually working, rather than continue incremental correction.

## Known regressions vs. dev.81 (accepted by the user)

1. Equipment matching is unscoped by attribute name — a coincidental text match elsewhere on an object could bind it to the wrong user.
2. Assets cache snapshot size and refresh time regress to dev.63 levels (previously fixed in dev.71/dev.72).
3. Users beyond the first 1,000 Jira accounts are not cached (previously fixed in dev.65).
4. The PDF renderer has no dependency-free fallback and no isolated browser profile; if Edge/Chrome headless fails under the MeshCentral service context (as it did in real dev.63/65/66 smoke), protocol execution fails outright instead of producing a plain-text PDF.
