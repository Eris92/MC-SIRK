# SIRK Management Platform 0.1.1-dev.90

Date: 2026-08-13
Status: development pre-1.0, real MeshCentral acceptance pending

## Scope

Guarantee that Jira protocol Output shows only the equipment table even when a historical result or a backend process that has not restarted still supplies the previous printable protocol text in `result.output`.

## Root cause

The dev.88 frontend understood the new equipment-table JSON contract, but still trusted `result.output`. A loaded new frontend combined with a stale backend process or an older stored result therefore rendered the former full protocol text below the new heading and action row.

## Correction

- Detect protocol results through their normalized `result.data.assets` payload.
- Build the visible `meshTable` JSON directly from those normalized assets.
- Keep only Hostname, Producent, Model, Numer seryjny, Numer inwentarzowy and Asset ID in the primary Output.
- Move the original result text to `Debug / raw output`, including when `rawOutput` is absent.
- Preserve the operation heading and shared `Copy`, `Open PDF`, `Download PDF` action row.
- Leave all non-protocol results unchanged.

## Verification

- Jira runtime regression requires the client-side stale-output override and canonical equipment schema.
- Shared structured-table and stable first-paint regressions pass.
- JavaScript syntax and `git diff --check` pass.
- Full `npm test` required before integration.
