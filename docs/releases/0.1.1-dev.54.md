# SIRK Management Platform 0.1.1-dev.54

## Jira Asset Protocol usability and cache

The user scope and Jira account selection now share one native MeshCentral dialog. `Tylko aktywni użytkownicy` is checked by default but can be cleared for the exceptional inactive-account case. A separate search field filters a visible, scrollable single-select user list locally by name, e-mail or identifier, so typing does not issue Jira requests. A double click selects the user and advances through the existing native dialog lifecycle.

The equipment step is a bounded checkbox list and carries every selected value into the existing authoritative server-side reassignment check. The canonical AQL covers `Sprzęt użytkownika` and all of its descendant types instead of only `Komputer`. Transfer and return are presented as mutually exclusive radio choices; explanatory copy is removed from all three steps.

Jira users and Jira Assets have separate persisted cache files with 24-hour freshness and stale fallback. Assets are cached per script-owned AQL, allowing other scripts to reuse the same owner without copying Jira request code. `Jira Cache Users.ps1` and `Jira Cache Assets.ps1` expose explicit execution with an optional Force switch.

## Operator identity and PDF

`Osoba IT` is selected from current MeshCentral users. The authenticated operator's real name is selected by default and the backend resolves it again against the MeshCentral user store before execution.

The protected artifact is rendered from styled A4 HTML using local Chrome or Edge. It restores a document header, metadata block, repeated equipment table headers, confirmation and signature fields. Branding is loaded from `server/assets/protocol-logo.svg`; no data URI or logo payload is duplicated in the PowerShell script.
