## Approval confirmation UX, direct message defaults and AD/SMS workflow corrections

Real MeshCentral smoke on dev.120 showed approval/message UX gaps, followed by AD workflow evidence from the same not-yet-integrated candidate: built-in SMS/mail scripts still defaulted to Level 1 approval, requester-confirmed Jira requests stayed in the actionable view while CMDB finalization was running, the confirmation UI exposed only the generic Jira Asset Protocol description, and the AD reset dialog used an unsearchable standalone AD list with mojibake Polish text and login-oriented SMS copy.

Changes:

- make built-in `Send SMS`, `Send Voice SMS` and `Send mail through SMTP Relay` default to no pre-approval;
- keep the direct-execution exception scoped to the existing stable `SmsSend`, `VmsSend` and `RelayMailSend` workflow identities, so ordinary My Scripts with an empty approval list still retain the configured Level 1 fallback when `allowNoApproval` is disabled;
- continue honoring explicitly configured Level 1/2/3 approval on those message workflows;
- after native requester confirmation is accepted, reuse the existing `confirming` state immediately in Approval Center and remove that request from the local actionable view before waiting for Jira finalization;
- keep the backend approval service as the authoritative confirmation/finalization owner; success and failure still resolve to the persisted `completed` / `failed` state with existing replay and concurrency guards;
- show authoritative prepared Jira protocol context as `User:` and changed `Assets:` in actionable cards, table summaries and the native confirmation dialog;
- derive that context only from the already prepared public `result.data`; no extra Jira request, timer, polling loop, observer or second lifecycle owner is added;
- make `Reset user password and SMS` reuse the canonical Jira users cache, then intersect it with one bounded AD directory result by case-insensitive `Jira emailAddress -> AD UserPrincipalName` matching; visible labels remain the Jira cache labels while submitted values remain AD `sAMAccountName` identities;
- reuse the existing shared parameter-dialog list/search filter via `SirkVariableSearch`, so typing filters the already loaded reset-user list locally and adds no per-keystroke Jira/AD request;
- store both current AD workflow scripts as UTF-8 with BOM so Windows PowerShell 5.1 and the browser-facing metadata preserve Polish characters;
- change account-create SMS text to `Konto w domenie <domain>, zostało utworzone. Tymczasowe hasło:` followed by a blank line and the generated password, without login/UPN;
- change reset SMS text to `Hasło w domenie <domain>, zostało zmienione. Tymczasowe hasło:` followed by a blank line and the generated password, without login;
- preserve requester/SiteAdmin authorization, Cancel -> Rejected behavior, protected PDF, Jira CMDB exactly-once semantics, AD OU allowlist, cryptographic password generation, AD mobile re-read, unlock and ChangePasswordAtLogon behavior.

Verification:

- `test/approval-message-ux.test.js` covers direct message defaults, the ordinary-script fallback boundary, immediate `confirming` transition ordering and Jira User/Assets context reuse;
- `test/sms-ad-workflows.test.js` covers canonical Jira-cache reuse, case-insensitive UPN matching, no display-name fallback, AD-safe option values, shared local Search metadata, UTF-8 BOM/Polish labels and exact no-login SMS wording;
- existing SMSAPI, SMTP Relay, requester confirmation/cancellation, shared parameter-dialog, localization and Jira confirmation regressions remain required;
- full `npm test` and Windows interactive-shell smoke are required on the exact versioned PR head before merge.
