# SIRK Management Platform 0.1.126

Status: development pre-1.0. This is not a product release.

## Evidence

Real MeshCentral acceptance after `0.1.125` still showed no observable change in the Issue #382 AD selector or received SMS behavior. The `0.1.125` cache/bootstrap change therefore did not prove that the intended files were installed and loaded by the actual MeshCentral Windows service.

Source inspection found a concrete deployment defect in the maintained Git installer: its default `ServiceName` was `meshcentral.exe`, an executable-shaped value rather than the standard MeshCentral Windows service name. The installer also printed the cloned source version after startup without verifying the installed file tree or the runtime that actually loaded.

## Correction

- The installer auto-detects the actual MeshCentral service. It first accepts the standard `MeshCentral` service and otherwise requires one unique service whose command belongs to the configured MeshCentral root. `-ServiceName` remains an explicit override for non-standard installations.
- The complete staged runtime artifact is hashed with SHA-256 and compared with the installed plugin tree after replacement.
- `config.json` in the installed target must match the staged development version before service start.
- `SIRKPortal.js` writes a small non-secret `sirk-platform-data/runtime-state.json` marker containing the on-disk version, loaded runtime version, PID and actual plugin root.
- Before service start the installer removes the previous marker, waits boundedly for a fresh one, and reports success only when both versions equal `0.1.126` and the reported plugin root is the installed `SIRKPortal` target.
- No MeshCentral core patch, polling loop, browser observer or AD/SMS workaround is added.

## Scope boundary

The current AD DirectoryServices bridge and UTF-8 SMS transport remain unchanged. Issue #382 is evaluated again only after the deployment path proves which runtime is active. A separate persistent My Scripts source/execution split discovered during diagnosis is recorded as evidence but is not changed in this deployment-scope revision.
