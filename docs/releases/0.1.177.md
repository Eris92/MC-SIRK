# 0.1.177 - Move Requests verified device membership

- Prevent false `completed` for an already-current move based only on potentially stale `GetNodeWithRights` data. A bounded `db.Get` must confirm the target `meshid` first.
- Prefer the same DB owner used by the visible device inventory when performing a move and verifying it. Reject if the canonical inventory DB lacks required write/read APIs instead of writing to a different owner.
- Reuse the existing Move Request provider, authorization and serialized approval lifecycle; no new polling, retries, or permissions.
- Targeted regressions for stale node state and divergent databases; existing positive/negative move tests remain part of CI.
- The prior production report of `completed` with an unmoved device still requires a real MeshCentral reproduction to establish whether there is a separate overwrite or UI sync cause.
- Development build only; no tag or GitHub Release.
