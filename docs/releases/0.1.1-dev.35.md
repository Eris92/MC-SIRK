## Root cause and changes

### Results viewer — complete the real Modern `showModal` contract

Current MeshCentral Modern `showModal(modalId, okButtonId, ...)` shows the modal and then unconditionally binds the supplied OK button. Dev.34 called only `showModal("xxAddAgentModal")`.

That sequence explains the exact real screenshot:

1. `setModalContent()` creates the opaque native surface and placeholder;
2. `showModal()` displays title/body/footer;
3. host code then dereferences the missing `okButtonId` and throws;
4. `openViewer()` never reaches `appendResult(host, ...)`;
5. the visible modal body remains empty.

Dev.35 changes only the existing Results owner call to:

```text
showModal("xxAddAgentModal", "idx_dlgOkButton")
```

The existing canonical `appendResult()` renderer, Copy, CSV Download, structured output/filtering and Debug/raw output remain unchanged. Classic continues to use `setDialogMode(2, ..., 1, ...)`. No new modal, CSS surface, observer, polling or timer was added.

### Network Settings — Windows-verified Shell PIDL properties execution

A temporary Windows Server 2025 GitHub runner diagnostic was used before changing runtime. The diagnostic workflow was reverted and is not part of the final diff.

The Windows evidence established:

- preferred default route selection resolves a live adapter by stable `InterfaceIndex`;
- `Shell.Application.Namespace(49)` successfully binds Network Connections;
- the exact adapter `FolderItem` is found by its live adapter name;
- `FolderItem.Path` is only a namespace GUID, so treating it as a normal executable/file path is invalid;
- `SHGetIDListFromObject()` on that real `FolderItem` returned `S_OK` and a non-null PIDL.

Therefore dev.35 keeps the existing deterministic IPv4-first/IPv6-fallback route selection and Network Connections enumeration, but removes the locale-sensitive:

```text
$item.InvokeVerb('properties')
```

The already-resolved Shell `FolderItem` is instead passed to a bounded one-shot interop block inside the existing command process:

1. `SHGetIDListFromObject` obtains its PIDL;
2. `ShellExecuteEx` receives `SEE_MASK_INVOKEIDLIST` (`0x0000000C`);
3. canonical Shell verb `properties` is invoked against that PIDL;
4. the PIDL is always released with `CoTaskMemFree`;
5. Shell failures are surfaced instead of falling back to a random adapter or panel-only success.

The existing `runAsUser: 2` policy and logged-on-user scheduled-task/VBS launcher remain the single interactive-desktop owner. Hidden Network Settings PowerShell remains window style 0; ordinary PowerShell/CMD/MMC behavior is unchanged. No second launcher, polling loop or fixed UI sleep was added.
