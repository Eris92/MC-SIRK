# 0.1.1-dev.49

Date: 2026-08-11
Status: development candidate for real Jira + MeshCentral smoke; not a product release.

## Jira integration ownership

- Make the global Jira integration connection-oriented: URL, account email, write-only API token, optional Cloud ID / Assets workspace ID and TLS verification remain global.
- Jira readiness no longer depends on one global project key. Jira user discovery remains instance-wide and independent of project selection.
- Remove global Project key, Hostname attribute, Asset field ID, Assets AQL scope, Max asset results and Assets/CMDB query-policy controls from Admin.
- Preserve legacy stored Jira scope values for backward compatibility only; the dynamic Assets provider no longer treats them as authoritative.

## Script-owned Jira Assets scope

- Reuse the existing script header metadata owner for `SirkJiraAssetAql`, `SirkJiraAssetLabelAttribute`, optional `SirkJiraAssetMaxResults` and optional `SirkJiraAssetUserVariable`.
- The canonical Jira Asset Protocol owns `objectType = Computer`, `Hostname` and its `JiraUser` binding inside the script instead of constraining every Jira script globally.
- Dynamic Assets options paginate Atlassian AQL pages with bounded provider/UI safety limits. Scripts without a user binding can expose their whole script-owned AQL scope; scripts with a binding fail closed until that selected user exists.
- The Jira Asset Protocol authoritative execution recheck reuses the same script-owned policy.

## Audit / bulk usage

- The interactive selector safety bound is provider-local and is not a global Jira data cap.
- Scripts assigned the Jira system credential retain direct Jira connection environment values and can implement their own full API pagination for inventory/audit exports without inheriting the interactive selector AQL or result limit.
