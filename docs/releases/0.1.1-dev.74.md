# 0.1.1-dev.74

Date: 2026-08-12
Status: development pre-1.0, real MeshCentral/Jira acceptance pending

## Scope

Correct the remaining Jira Asset Protocol user-to-equipment bridge after real `0.1.1-dev.73` smoke still produced an empty `Sprzęt do protokołu` list.

## Root cause

The dev.73 identity-object classifier advertised Polish user/person object support but matched only singular lexical forms such as `pracownik` and `osoba`. Common real Jira Assets object type names use plural forms such as `Pracownicy` and `Osoby`; those strings do not contain the singular tokens, so the selected Jira account was never recognized as the matching workspace identity object and its Assets id/key aliases were never derived for equipment-reference matching.

## Changes

- Reuse the existing `server/core/jira-asset-service.js` identity bridge and widen only its user-like object-type classifier to stable Polish stems `pracowni` and `osob`.
- Preserve existing English `Users`/person/employee and Polish `uzytk`/`użytk` matching.
- Keep direct Jira-user references, schema-v4 compact reference identities, assignment-semantic plain-text restrictions, bounded snapshot reuse and identity-object exclusion unchanged.
- Add no Jira request, polling loop, timer, observer, cache owner or browser-side authority.
- Keep Assets cache schema v4; existing v4 snapshots already contain the object type and reference identities required by this matcher-only correction.
- Change the focused reference-cache regression fixture from `Users` to `Pracownicy`, so both fresh and persisted-cache bridge paths fail on dev.73 and pass only with the localized plural classifier correction.
