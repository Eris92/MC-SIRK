## Jira selected-user equipment scope correction

Real `0.1.1-dev.77` smoke still returned an empty `Sprzet do protokolu` list. The failed dev.76/dev.77 approach widened one static AQL source before server-side matching. That could remove the previously working PC path when the broader source or reference assumptions did not match the real tenant.

This build changes the ownership boundary instead of widening the static script source again:

- restore the canonical protocol/cache AQL to the real-smoke-working `objectType in objectTypeAndChildren("Sprzet uzytkownika")` anchor;
- keep that anchor query and result independently, so a heterogeneous expansion failure cannot erase working PC results;
- for a selected Jira user only, resolve accountId/email/displayName from the existing Jira users cache and execute one additional targeted AQL using `anyAttribute` / `Label` plus inbound/outbound reference functions;
- merge/dedupe targeted heterogeneous results with the working anchor;
- keep unbound `Jira Cache Assets` on one shared static query; no workspace-wide `Key is not EMPTY` scan and no unqualified all-reference scan;
- preserve the existing `jira-asset-service.js` cache, matching, bounded pagination/concurrency and Jira protocol authoritative recheck; the new adapter only supplies the selected-user query scope.

The targeted expansion is fail-soft: if Jira rejects or cannot resolve the additional selected-user AQL, the selector still returns the working anchor result and exposes a bounded warning instead of becoming empty.
