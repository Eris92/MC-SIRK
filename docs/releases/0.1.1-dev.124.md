## AD reset selector CLIXML and module-load correction

Real MeshCentral smoke rejected `0.1.1-dev.123`: the reset user selector remained empty and the native parameter dialog exposed raw Windows PowerShell `#< CLIXML` progress/error serialization. The serialized Active Directory module-loading text also contained mojibake.

Root cause / decisions:

- the dev.123 selector still launched Windows PowerShell and synchronously imported the `ActiveDirectory` module before running `Get-ADUser`; module/provider initialization emitted progress records and remained on the selector hot path;
- when that child process failed or exceeded its timeout, `ad-directory-service.js` exposed raw `stderr`, so redirected Windows PowerShell CLIXML became visible UI content and its stream encoding appeared as mojibake;
- keep `server/core/ad-directory-service.js` as the AD matching owner and the existing Jira user cache as the source of requested identities; remove the ActiveDirectory PowerShell module from only the selector query path instead of adding another cache, request loop or UI workaround.

Changes:

- add the direct implementation dependency `server/core/ad-directory-query.ps1`, which performs the bounded UPN lookup with `System.DirectoryServices.DirectoryEntry` / `DirectorySearcher` and configured AD credentials, without `Import-Module ActiveDirectory`, `Get-ADUser` or the default `AD:` provider drive;
- keep case-insensitive Jira `emailAddress -> UserPrincipalName` matching and the AD `sAMAccountName` option value used later by the reset workflow;
- query only requested Jira-cache UPNs in escaped LDAP OR chunks of 1000, with server/client time limits and one PowerShell child process; an empty Jira identity set still skips AD entirely;
- suppress progress/warning/verbose/information streams in the machine bridge and write the JSON envelope directly as explicit UTF-8 bytes to standard output;
- parse only the JSON stdout envelope in Node. Raw PowerShell `stderr`/CLIXML is never copied into the parameter dialog; timeouts return the bounded `Active Directory user lookup timed out.` message and other process failures use a short generic error unless the JSON bridge supplied a clean error;
- reduce the Jira-backed selector process timeout to 15 seconds while preserving the existing local Search behavior and no per-keystroke AD/Jira requests;
- keep the dev.123 SMS percent-encoded UTF-8 transport unchanged because the new real evidence identifies the selector child-process stream as the source of the visible dialog mojibake; received SMS still remains real-environment acceptance evidence for Issue #382.

Verification gate:

- `test/sms-ad-real-smoke-regression.test.js` covers the one-process bridge, stdin identity transport, no ActiveDirectory module/cmdlet dependency, bounded timeout, no CLIXML/mojibake error leak, explicit UTF-8 machine errors and the existing SMS form contract;
- `test/windows-ad-selector-bridge-smoke.ps1` parses the bridge under the maintained Windows PowerShell 5.1 runner and verifies required DirectoryServices/UTF-8/progress-isolation contracts without contacting a real directory;
- existing Windows Network Connections and SMS UTF-8 smokes remain in the same CI job;
- exact `0.1.1-dev.124` Linux full `npm test` and Windows smoke must be GREEN before merge.

No tag or GitHub Release is created. Issue #382 remains OPEN until real MeshCentral confirms prompt selector population with no CLIXML and real SMSAPI delivery confirms Polish message characters.
